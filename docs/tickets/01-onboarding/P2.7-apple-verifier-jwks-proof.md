# P2.7 — Prove the real Apple verifier against a local JWKS fixture

Phase: 2 · Backend auth
Track: backend
Execution: **autonomous**
Depends on: P0.8
Supersedes: OB-17

## Goal
Exercise the real `src/lib/apple.ts` verification path with locally minted tokens and a served JWKS fixture, proving forged/wrong-aud/wrong-iss/expired all reject and a valid token passes.

## Context and design direction
Read `_DESIGN.md` and `_RUNBOOK.md` before editing. `apps/api/src/lib/apple.ts` is real but has 0% test coverage: it builds a module-scope `createRemoteJWKSet(new URL('https://appleid.apple.com/auth/keys'))` (lines 3–5) and `verifyAppleIdentityToken` (lines 14–25) runs jose's `jwtVerify` with `issuer: 'https://appleid.apple.com'` and `audience: bundleId` (jose checks `exp` by default), then requires `sub` and a string `email` claim. Every existing test bypasses it: `test/auth-apple.test.ts` lines 6–8 define `appleEnv(...)` which injects `APPLE_IDENTITY_VERIFIER` fakes through the route seam at `src/routes/auth.ts` line 20 (`c.env.APPLE_IDENTITY_VERIFIER ?? verifyAppleIdentityToken`). jose is already a dependency (`apps/api/package.json`). This ticket builds a local cryptographic proof — no network, no real Apple. This ticket is deliberately scoped so another fresh agent can verify and land it independently.

## Files
- `apps/api/test/apple-verifier.test.ts` (new)
- `apps/api/src/lib/apple.ts` (ONLY if a minimal JWKS-injection seam proves necessary — see Approach 2)

Verifier proof only; the existing route tests in `test/auth-apple.test.ts` keep their injected fakes — do not rewrite them.

## Approach
1. In-test key material (jose, already installed): `generateKeyPair('RS256')` (Apple signs with RS256), `exportJWK(publicKey)` with a `kid`, wrap as `{ keys: [jwk] }`. Mint tokens with `new SignJWT({ email: '...' }).setProtectedHeader({ alg: 'RS256', kid }).setSubject(...).setIssuer(...).setAudience(...).setExpirationTime(...)`.
2. Serve the fixture to the REAL module. Preferred: the workers vitest pool's `fetchMock` from `cloudflare:test` (declarative outbound-fetch interception) stubbing `GET https://appleid.apple.com/auth/keys` to return the fixture JWKS — this exercises `apple.ts` completely unmodified. Fallback if `fetchMock` cannot intercept jose's fetch in this pool version: add the smallest possible seam to `apple.ts` (e.g. export a `makeAppleVerifier(getKey)` factory whose default is the existing remote JWKS; `verifyAppleIdentityToken` stays the default export with identical production behavior) — and justify the fallback in the ledger.
3. Test matrix against `verifyAppleIdentityToken(token, 'com.savoro.Savoro')` (bundle id per the iOS project; the value is arbitrary for the proof as long as mint and verify agree):
   - valid token (right iss/aud/exp, signed by the fixture key) → resolves `{ sub, email }`;
   - **forged signature**: same claims signed by a DIFFERENT key not in the JWKS → rejects (name it, e.g. `'a forged signature is rejected'`);
   - wrong `aud` → rejects;
   - wrong `iss` → rejects;
   - expired (`exp` in the past) → rejects;
   - missing `email` claim on an otherwise-valid token → rejects (`apple.ts` lines 20–22).
4. Beware module-scope caching: the JWKS set at `apple.ts` line 5 is created once per isolate and jose caches fetched keys — serve ONE fixture JWKS for the whole file and derive all cases from claims/keys, not from swapping JWKS responses mid-file.
5. Leave `test/auth-apple.test.ts` untouched: route-level behavior (fake-verifier seam) and verifier-level proof are complementary suites.

### Implementation sketch
```ts
// test/apple-verifier.test.ts (shape, not final code)
import { fetchMock } from 'cloudflare:test'
import { SignJWT, generateKeyPair, exportJWK } from 'jose'

const { publicKey, privateKey } = await generateKeyPair('RS256')       // fixture signer
const { privateKey: rogueKey } = await generateKeyPair('RS256')        // forger, absent from JWKS
const jwks = { keys: [{ ...(await exportJWK(publicKey)), kid: 'fixture-key', alg: 'RS256' }] }

fetchMock.activate()
fetchMock.get('https://appleid.apple.com')
  .intercept({ path: '/auth/keys' }).reply(200, jwks).persist()

const mint = (key: CryptoKey, over: Partial<{ iss: string; aud: string; exp: string }> = {}) =>
  new SignJWT({ email: 'a@example.com' }).setProtectedHeader({ alg: 'RS256', kid: 'fixture-key' })
    .setSubject('apple_sub_1').setIssuer(over.iss ?? 'https://appleid.apple.com')
    .setAudience(over.aud ?? 'com.savoro.Savoro').setExpirationTime(over.exp ?? '1h').sign(key)
// valid → resolves; mint(rogueKey) / wrong aud / wrong iss / exp:'-1h' → await expect(...).rejects
```

## Done when
- All six matrix cases pass; full suite + typecheck green; no network egress to Apple during tests.
- `src/lib/apple.ts` is exercised for real: production behavior byte-identical if the fetchMock path worked (file untouched), or the seam is provably default-equivalent (same URL, issuer, checks) if the fallback was needed.
- The four rejection cases each assert a rejection (thrown/rejected), not merely "not equal to valid".
- Required negative witness: in a scratch copy of `apple.ts`, skip the signature check (e.g. decode claims without verification via `decodeJwt` and run only the claim checks) — `'a forged signature is rejected'` goes red. Record the exact red assertion, restore, rerun green.

## Watch out
- If `fetchMock` in the installed `@cloudflare/vitest-pool-workers` (^0.8.36) cannot intercept jose's JWKS fetch, do not fight it for hours — take the documented seam fallback, keeping the production default untouched at the call site (`routes/auth.ts` line 20 still resolves to the real verifier when no injection is present).
- Never point the module at a live URL you stand up on localhost inside CI — the fixture must be hermetic.
- Do not loosen `apple.ts` (e.g. removing the email/sub requirement at lines 20–22) to simplify minting — mint richer tokens instead.
- Module-scope JWKS caching means test ORDER can hide failures if you swap key sets between tests; one JWKS fixture per file, as in Approach 4.
- If compiled reality differs (verifier already tested, seam already exists, algorithm differs), follow the repo and note the delta; if `jose`'s API in the installed version lacks what this packet names, mark blocked with the version and the failing import rather than downgrading dependencies.
