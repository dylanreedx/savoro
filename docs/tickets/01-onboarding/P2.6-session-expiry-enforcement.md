# P2.6 — Pin session expiry enforcement with regression tests

Phase: 2 · Backend auth
Track: backend
Execution: **autonomous**
Depends on: P2.5
Supersedes: OB-16

## Goal
Put session expiry under test at the middleware chokepoint so the currently-untested `expiresAt` behavior can never silently regress.

## Context and design direction
Read `_DESIGN.md` and `_RUNBOOK.md` before editing. A correction to the epic's claim that expiry is "not enforced": the chokepoint query ALREADY enforces it. `findUserIdByToken` (`apps/api/src/repo/sessions.ts`, lines 7–15; called from `src/middleware/auth.ts` line 16) filters `gt(sessions.expiresAt, now)` alongside the revocation check (line 11), with `now = new Date().toISOString()`. What is true is that it has ZERO coverage: `test/auth.test.ts` contains exactly three tests (no token, unknown token, seeded valid token — lines 7, 14, 23) and every seeded session uses the far-future `2099-01-01T00:00:00Z` expiry (`test/seed.ts` line 12; `seed/local-dev.sql` line 17). Sessions are issued with a 30-day expiry (`src/repo/sessions.ts` line 39). So this ticket is test-first: pin the existing behavior; change `src/` only if a test exposes a genuine defect. This ticket is deliberately scoped so another fresh agent can verify and land it independently.

## Files
- `apps/api/test/auth-expiry.test.ts` (new)
- `apps/api/test/seed.ts` (add an expiry-configurable session seed helper)
- `apps/api/src/repo/sessions.ts` (ONLY if a test exposes a real enforcement defect)

Tests are the deliverable; treat the `src/` entry as a contingency, not an invitation — do not absorb refactors.

## Approach
1. Extend `test/seed.ts` with a helper that seeds a session with caller-supplied `expires_at` and `revoked_at` (generalize `seedUser`'s insert at lines 10–13 without changing its signature or its 12 existing call-site tests' behavior).
2. Write `test/auth-expiry.test.ts`, probing through the REAL middleware exactly like `test/auth.test.ts` (`GET /v1/logs/day?date=2026-06-10`):
   - **expired**: session with `expires_at` in the past → 401 `unauthorized` envelope (name it, e.g. `'an expired session is rejected by the middleware'`);
   - **nearly-expired-still-valid**: `expires_at` a few minutes in the future → 200 (expiry is exclusive-of-now, not fuzzy);
   - **boundary sanity**: `expires_at` equal to a just-captured now-ish instant is rejected (`gt`, not `gte` — pin whichever the contract/implementation defines; today it is strict `gt`);
   - **revoked + expired**: both conditions set → 401 (the predicates compose, order-independent);
   - **format robustness**: an expired timestamp written in the seed convention (`2020-01-01T00:00:00Z`, no milliseconds) rejects — this pins that the lexicographic TEXT comparison against `toISOString()` (which HAS milliseconds) behaves correctly across the repo's two ISO variants.
3. If any test fails against current `src/`, you have found a real defect: fix it INSIDE `findUserIdByToken` only — the single chokepoint per `_DESIGN.md` §5 — and document the before/after.
4. Confirm no route bypasses the chokepoint: grep `src/` for direct `sessions` queries outside `repo/sessions.ts`; report anything found (do not fix out-of-fence).

### Implementation sketch
```ts
// test/seed.ts — additive helper; seedUser (lines 5–14) stays untouched
export async function seedSession(
  db: D1Database,
  opts: { userId: string; token: string; expiresAt: string; revokedAt?: string | null },
): Promise<void> {
  await db
    .prepare('insert into sessions (id, user_id, token_hash, expires_at, created_at, revoked_at) values (?, ?, ?, ?, ?, ?)')
    .bind(`ses_${crypto.randomUUID()}`, opts.userId, await hashToken(opts.token), opts.expiresAt, NOW, opts.revokedAt ?? null)
    .run()
}
```

## Watch out
- The epic text ("expiresAt … not enforced") predates the current code — if you land a `src/` "fix" for behavior that already works, that is out-of-fence noise; prove a red test first.
- Do not fake time by editing `findUserIdByToken` to accept an injectable clock unless a test genuinely cannot be written with seeded timestamps — seeded past/future `expires_at` values are sufficient here.
- `expires_at` is a TEXT column compared lexicographically; keep all test timestamps in ISO-8601 UTC with the `Z` suffix like the rest of the repo, or you will pin an artifact of string ordering.
- Don't touch session ISSUANCE (the 30-day window at `src/repo/sessions.ts` line 39) — window policy belongs to the approved contract, not this ticket.
- If the boundary or format tests reveal the strict-`gt` semantics contradict the approved contract's stated expiry rule, mark blocked quoting both, rather than changing the predicate silently.
