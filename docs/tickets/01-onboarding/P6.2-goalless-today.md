# P6.2 — Implement the designed goal-less Today

Phase: 6 · Goal-less mode and Profile
Track: frontend
Execution: **autonomous**
Depends on: P6.1, P0.8
Supersedes: OB-37

## Goal
Render the approved goal-less Today: bare totals with no denominators and no progress copy, plus one
calm add-targets affordance routing into the targets flow.

## Context and design direction
Read `_DESIGN.md` and `_RUNBOOK.md` before editing. This is the real first-run state for every user
who skips targets, and it currently has zero snapshot evidence. P6.1 already makes nil goals arrive
honestly: `TodaySummaryViewModel.goals` is optional, `SavoroMacroValue` renders value-only via its
nil branch (`SavoroPrimitives.swift:528`), and `SavoroMacroRing` accepts a nil goal. This ticket
designs what nil LOOKS like per the approved pack: totals as facts ("1,420 cal", "82 g"), no ring
denominator, none of the progress support copy (`TodayPlaceholderView.swift:143-152` must be
unreachable without a goal), and a single calm affordance ("Add daily targets"-energy) that routes
to the P5.6 targets flow. Skipping is a designed mode, not a degraded one (locked decision 7). All
P6 screens must match the approved design pack in docs/tickets/01-onboarding/design/, post-P0.8.
This ticket is deliberately scoped so another fresh agent can verify and land it independently.

## Approach
1. Add an explicit goal-less presentation branch keyed on `viewModel.goals == nil`: the calorie card
   shows the day's total as a bare number (reuse `SavoroMacroRing` with nil goal or the layout the
   design pack specifies), macro rows use `displayValue` (no "/"), and the progress-bar fill
   semantics are absent, not zero-filled.
2. Suppress every progress artifact when goal-less: no `calorieSupportText`, no
   `macroProgressSubtitle` ("…against your private daily goals", line 154–156, presumes a goal), no
   fraction-driven UI.
3. Add ONE add-targets affordance built from L-35 primitives — calm, secondary-weight, copy per the
   design pack (invitation, not correction) — that presents the P5.6 `CaloriesFirstTargetsEditor`
   flow; on a successful goal POST, Today refreshes into the goal state.
4. Keep the goal state pixel-identical: fixture-goal snapshots must not shift.
5. Tests in `ScaffoldTests.swift`: with `goals: nil`, the concatenation of every visible string from
   the view model contains neither "/ 0" nor "0 cal" as a denominator nor any of {"target",
   "progress", "goal"} phrased as progress copy — at minimum assert `"/ 0 cal"` and
   `calorieSupportText`-emptiness explicitly; the affordance copy is banned-copy-clean; the
   affordance routes to the targets flow (routing intent unit test).
6. Snapshot the goal-less Today across the full matrix; named states: `goalless-empty-day` and
   `goalless-with-logs` (both from the design pack).

## Done when
- Goal-less Today renders bare totals with no denominators, no ring denominator text, and zero
  progress copy — unit tests assert `"N / 0 cal"`-shaped strings cannot appear (explicit
  `XCTAssertFalse(copy.contains("/ 0"))`-style check over all view-model outputs).
- One add-targets affordance exists, routes to the P5.6 flow, and refreshes into the goal state
  after a successful POST (mock-client test).
- Snapshot matrix {light,dark} × {standard,XXXL} for `goalless-empty-day` and `goalless-with-logs`;
  goal-state references unchanged.
- All new strings banned-copy-clean; full iOS suite green with the grown snapshot count.

## Watch out
- Banned copy list applies (no failure/failed/guilt/etc.) — the affordance must not imply the user
  is missing something ("You haven't set goals" is out; "Add daily targets if you want context" is
  the energy).
- Build from L-35 design-system primitives; no raw padding/colors; match the goal-state card rhythm
  (`TodayLayout` constants, TodayPlaceholderView.swift:163+).
- Snapshot reference counts in `Scripts/record-snapshots.sh` grow deliberately in this ticket only;
  never re-record goal-state references.
- P6.1 must be `done` on `main` first; if nil still collapses anywhere, mark blocked with evidence
  rather than papering over it visually.
- If the approved design pack shows a different goal-less layout than this packet sketches, the pack
  wins — it is the locked artifact; mark blocked if the pack is missing a goal-less spec.
