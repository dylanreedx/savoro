# P5.1 — Build the welcome/auth screen

Phase: 5 · Onboarding UI
Track: frontend
Execution: **autonomous**
Depends on: P4.5, P0.8
Supersedes: OB-28

## Goal
Ship the first screen a signed-out user sees: Sign in with Apple plus a "Continue with email" path,
with privacy-first copy and honest loading/error states.

## Context and design direction
Read `_DESIGN.md` and `_RUNBOOK.md` before editing. Today no auth UI exists anywhere:
`SavoroIOS/Savoro/Features/` has no `Onboarding/` directory and the app boots straight into five
tabs. P4.5's root state machine owns `signedOut → onboarding(step) → authenticated`; this screen is
the `signedOut` root. Apple sign-in goes through P4.2's `ASAuthorizationController` adapter
(protocol + DEBUG mock), so simulators and tests exercise the full flow without entitlements. Both
methods converge on the same opaque bearer session (locked decision 1). All P5 screens build ONLY
after the P0.8 design verdict and must match the approved design pack in
docs/tickets/01-onboarding/design/. This ticket is deliberately scoped so another fresh agent can
verify and land it independently.

## Files
- `SavoroIOS/Savoro/Features/Onboarding/WelcomeAuthView.swift` (new — view + view model)
- `SavoroIOS/SavoroTests/OnboardingTests.swift` (new — state + copy unit tests; later P5 tickets
  extend it)
- `SavoroIOS/SavoroTests/SnapshotTests.swift` (add welcome-auth snapshot cases to the existing class
  — the record script targets `-only-testing:SavoroTests/SnapshotTests`)
- `SavoroIOS/Scripts/record-snapshots.sh` (bump `expected_snapshot_count`, currently 18)

This fence is the one new screen plus its evidence; do not absorb adjacent work (no email form
fields — that is P5.2; no root-state-machine changes beyond presenting this view).

## Approach
1. Create `Features/Onboarding/WelcomeAuthView.swift` with an observable view model exposing an
   explicit state enum: `idle`, `appleInFlight`, `emailEntryHandoff` (routes to P5.2's forms),
   `error(message:)`.
2. Compose entirely from L-35 primitives (`SavoroCard`, `SavoroTypography`, `SavoroSpacing`,
   `SavoroColor`, existing button/pill styles) — no raw padding, colors, or ad-hoc fonts.
3. Apple button invokes the P4.2 adapter protocol; on success hand the credential to the P4.5 state
   machine's Apple-exchange path; on cancel return to `idle` without an error banner; on real errors
   show calm copy (never "failed").
4. "Continue with email" transitions to `emailEntryHandoff`; P5.2 owns what renders there — here it
   is a navigation intent only.
5. Privacy-first supporting copy per the approved design pack (private by default, nothing shared
   without asking).
6. Unit tests in `OnboardingTests.swift`: state transitions (idle → appleInFlight → error → idle;
   cancel is not an error), and a banned-copy assertion over every visible string on this screen.
7. Snapshot the four named states in the existing `SnapshotTests` matrix; record via the script.

## Done when
- WelcomeAuthView renders states `idle`, `appleInFlight`, `emailEntry-handoff`, and `error`, each
  snapshotted in {light,dark} × {standard,XXXL} (16 new reference images; `expected_snapshot_count`
  grows by 8 — the script counts the 2 XXXL recordings per snapshot case).
- Apple flow runs end-to-end in DEBUG via the P4.2 mock adapter; user cancel returns to `idle` with
  no error UI.
- Every visible string passes the banned-copy assertion (no adherence/compliance/failure/failed/over
  limit/guilt/cheat/"bad food"/raw IDs/mock/scaffold/backend jargon).
- Full iOS suite green with the enlarged snapshot set.

## Verify

```bash
cd SavoroIOS && xcodebuild test -scheme Savoro -destination 'platform=iOS Simulator,name=iPhone 17'
```
Record references with `cd SavoroIOS && ./Scripts/record-snapshots.sh` after bumping the pinned

## Watch out
- Banned copy list applies (no failure/failed/guilt/etc.) — error state copy is the likely offender;
  write "That didn't go through — try again" energy, not "Sign-in failed".
- Build from L-35 design-system primitives; hand-rolled padding/raw colors are lint failures per
  `_DESIGN.md` §5.
- `Scripts/record-snapshots.sh` pins `expected_snapshot_count=18` today; grow it deliberately in
  this ticket only, and never re-record references owned by other tickets.
- The design pack directory `docs/tickets/01-onboarding/design/` is produced by P0.7 and approved at
  P0.8; if it is absent or the verdict is missing, mark this ticket blocked with evidence rather
  than inventing a layout.
- If P4.2/P4.5 landed with different names or seams than assumed here, follow compiled reality and
  note the delta in your report.
