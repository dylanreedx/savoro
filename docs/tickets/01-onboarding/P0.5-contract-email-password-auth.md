# P0.5 — Draft the email/password auth contract diff

Phase: 0 · Foundations and contracts
Track: backend
Execution: **autonomous**
Depends on: P0.1
Supersedes: OB-2 (docs/epics/onboarding.md)

## Goal
Produce a reviewable unified diff against `docs/api-contract.md` specifying `POST /v1/auth/signup`,
`POST /v1/auth/login`, and `POST /v1/auth/logout` with envelopes shaped like the existing Apple
exchange and a precise error taxonomy.

## Context and design direction
Read `_DESIGN.md` and `_RUNBOOK.md` before editing. Draft-only: contract edits are human-only
(`docs/loop-protocol.md` line 92; landed at the P0.8 gate). The shape to mirror is the existing
`POST /v1/auth/apple` section (`docs/api-contract.md` lines 135–152): request → response `{
"sessionToken": "<opaque bearer — returned once>", "user": { "id", "email", "displayName" } }`,
invalid credential → `unauthorized`. Server-side, `apps/api/src/routes/auth.ts` implements only the
`/apple` route (line 10) — no email/password endpoints or columns exist yet. Note the contract's
error-code list (`docs/api-contract.md` line 25) currently has no 409 code, so the diff must
introduce one (e.g. `conflict`) alongside the taxonomy. Locked decisions (`_DESIGN.md` §2, items
1–3): both auth methods converge on the same opaque session; passwords are PBKDF2 via WebCrypto
(Workers has no native bcrypt/argon2); no reset or verification at MVP. This ticket is deliberately
scoped so another fresh agent can verify and land it independently.

## Approach
1. Write an exact unified diff against current `docs/api-contract.md` (`a/docs/api-contract.md`
   paths, applies from the repo root), adding the three endpoints adjacent to the existing `POST
   /v1/auth/apple` section.
2. `POST /v1/auth/signup` — no auth. Request: `{ "email", "password" }`. Response `201` in the exact
   Apple-exchange envelope shape: `{ "sessionToken", "user": { "id", "email", "displayName" } }`
   (displayName null at signup — identity comes later per the P0.4 draft). Specify email
   case-normalization for uniqueness.
3. `POST /v1/auth/login` — no auth. Same request/response shape, `200`.
4. `POST /v1/auth/logout` — auth required. Revokes the presented session (sets `revokedAt`);
   subsequent use of that token is `unauthorized`. Response: `204`.
5. Error taxonomy, stated per endpoint:
   - `409` duplicate email on signup — requires adding a 409 code (propose `conflict`) to the
     Conventions error-code list;
   - `401 unauthorized` on bad login credentials, with unknown email deliberately indistinguishable
     from wrong password (uniform message and timing intent noted);
   - `422 validation_failed` for invalid or weak password on signup — state the minimum rule you
     propose (e.g. length floor) as a clearly labeled proposal.
6. Add a short "Password storage" note: PBKDF2 via WebCrypto, versioned parameters stored with the
   hash, constant-time verification, never plaintext at rest.
7. Add an explicit deferral line: password reset and email verification are post-core-gate; lockout
   recovery is manual re-issue via seed tooling (P1.4) — an accepted, documented limitation.
8. Validate with `git apply --check`.

## Done when

- PBKDF2 note and the reset/verification deferral are present.

## Watch out
- Do NOT edit `docs/api-contract.md` or any `apps/api/` file — the deliverable is one diff document.
- Do not spec reset, verification, rate limiting, or email sending "while you're at it" — explicit
  non-goals (`_DESIGN.md` §8).
- Do not leak whether an email is registered through the login error shape — that is the point of
  the 401 indistinguishability clause.
- Mirror the Apple envelope exactly; a second, differently-shaped auth envelope would force
  per-method branching downstream, which locked decision 1 forbids.
- If P0.4's diff also lands in `drafts/` and both touch nearby contract lines, that is fine — each
  must apply against the CURRENT contract independently (P0.8 lands them serially; minor rebase
  there is Dylan's step). If the packets conflict with compiled reality or a locked decision, mark
  blocked with evidence rather than improvising.
