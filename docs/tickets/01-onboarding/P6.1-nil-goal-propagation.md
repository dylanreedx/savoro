# P6.1 — Propagate nil goals as nil through the Today chain

Phase: 6 · Goal-less mode and Profile
Track: frontend
Execution: **autonomous**
Depends on: P0.8
Supersedes: OB-36

## Goal
Kill the `?? .zero` goal collapse so a user with no goal flows as `nil` — not zero — all the way to
the ring and macro rows, eliminating the "N / 0 cal" failure mode.

## Context and design direction
Read `_DESIGN.md` and `_RUNBOOK.md` before editing. The verified defect chain (every line checked
against the repo):

1. `SavoroIOS/Savoro/Core/API/LoggingRequests.swift:183` — `TodayAPIService.fetch` (lines 177–185)
   collapses a nil goal: `goals: goal.goal?.dailyTargets ?? .zero`. `CurrentGoalResponse.goal` IS
   already optional (lines 142–151), so the server's `{"goal": null}` decodes fine — the lie starts
   here, because `TodayLoadedData.goals` (lines 168–171) is a non-optional `MacroTotals`.
2. `Features/Today/TodayPlaceholderView.swift:78` — `TodaySummaryViewModel.goals` is non-optional
   `MacroTotals`; `macroValues` (lines 121–128) and `calorieProgress` (130–132) feed `goal:
   goals.calories` etc. — an Optional wrapping 0, never nil.
3. `DesignSystem/SavoroPrimitives.swift:515-529` — `SavoroMacroValue.goal` is ALREADY `Double?` with
   a working nil branch (`progressText`, line 528, falls back to `displayValue`). It renders "N / 0
   cal" only because step 2 feeds it 0 instead of nil. (This packet corrects the earlier claim that
   the primitive lacked a nil branch.)
4. `DesignSystem/SavoroPrimitives.swift:608-632` — the ring is named `SavoroMacroRing` (there is no
   `SavoroCalorieRing` in the repo): `let goal: Double` is non-optional (line 610), the fraction
   guard `goal > 0` (line 614) pins it at 0, and line 627 hard-codes "/ \(Int(goal)) cal". A second
   collapse feeds it: `TodayPlaceholderView.swift:413` passes `goal: viewModel.calorieProgress.goal
   ?? 0`.
5. `TodayPlaceholderView.swift:143-152` — `calorieSupportText` switches on `calorieProgressFraction`
   (guard at 138–141 returns 0 for a zero goal), so a goal-less user always reads "Still flexible —
   use this as context, not a score." — progress copy about a target that does not exist.
6. `Core/Models/NutritionModels.swift:302-351` — `Goal.dailyTargets` hard-decodes non-optionally
   (line 337). This type is not in the live Today decode path (that is `CurrentGoalResponse`), but
   it is a hard-decode landmine for any future goal payload without `dailyTargets`.

This ticket makes nil honest end-to-end; the designed goal-less rendering is P6.2. This ticket is
deliberately scoped so another fresh agent can verify and land it independently.

## Approach
1. `TodayLoadedData.goals: MacroTotals?`; `fetch` returns `goal.goal?.dailyTargets` directly.
2. `TodaySummaryViewModel.goals: MacroTotals?`; `macroValues`/`calorieProgress` pass
   `goals?.calories` etc. so `SavoroMacroValue.goal` is genuinely nil; `calorieProgressFraction` and
   `calorieSupportText` gain an explicit nil-goal branch (return no progress copy — P6.2 decides
   final wording; here, empty/absent beats lying).
3. `SavoroMacroRing.goal: Double?`; nil renders value-only (no "/ N cal", ring track without fill
   fraction semantics); update the two call sites (`TodayPlaceholderView.swift:411-417`,
   `SavoroDesignSystemGallery.swift:86`) and `ScaffoldTests.swift:2628`.
4. For `Goal` (NutritionModels): keep `dailyTargets` required if the contract guarantees it, but
   convert the `try!`-adjacent hard decode into a typed, testable decode error rather than removing
   it silently — verify against the approved P0.8 contract and record the choice.
5. Tests in `ScaffoldTests.swift`: a `TodaySummaryViewModel` built with `goals: nil` yields
   `progressText == displayValue` for every macro (no "/" anywhere), no support copy, ring receives
   nil; `CurrentGoalResponse` decoding `{"goal": null}` produces nil end-to-end through
   `TodayAPIService.fetch` (mock client).
