# P5.4 — Build the profile basics page

Phase: 5 · Onboarding UI
Track: frontend
Execution: **autonomous**
Depends on: P5.3, P3.3
Supersedes: OB-31

## Goal
Ship the profile basics step: an optional display name plus a private-by-default visibility
explainer, submitted via `PATCH /v1/me/profile`, advancing `onboardingState`.

## Context and design direction
Read `_DESIGN.md` and `_RUNBOOK.md` before editing. Privacy defaults hold (locked decision 14):
`profileVisibility` defaults to `private`; this page explains that, it does not ask the user to
choose sharing during onboarding. The server validates `displayName` as a trimmed 1–80 character
string when the field is present (`apps/api/src/routes/profiles.ts:81-91`) — so "optional" means the
client must OMIT the field entirely when left blank, never send an empty string. P3.3 makes `PATCH
/v1/me/profile` transition `onboardingState`; the P4.5 state machine follows the server's answer.
All P5 screens build ONLY after the P0.8 design verdict and must match the approved design pack in
docs/tickets/01-onboarding/design/. This ticket is deliberately scoped so another fresh agent can
verify and land it independently.

## Approach
1. Build `ProfileBasicsView` from L-35 primitives: a single optional display-name field, a calm
   explainer card stating the private-by-default posture (logs, goals, and progress stay private;
   sharing recipes later is a separate, explicit choice), and a continue action.
2. View model builds the PATCH payload: include `displayName` only when the trimmed input is 1–80
   characters; blank input sends a payload without the field. Client-side trim + length cap mirrors
   `profiles.ts:81-91`.
3. Submit through the P4.3 typed profile request; on success feed the response's `onboardingState`
   to the P4.5 state machine, which advances to the intent step.
4. Named states: `idle-empty` (name blank, continue enabled — it is optional), `idle-filled`,
   `submitting`, `error` (calm retry copy).
5. Unit tests: payload omits `displayName` when blank; trims whitespace; 80-char boundary; error
   copy banned-copy-clean; state machine advances on the server's returned state, not on optimistic
   assumption.
6. Snapshot every named state across the full matrix.

## Done when
- Continue works with the name left blank (skip-equivalent) and with a valid name; both paths
  advance `onboardingState` via the server response.
- A blank field never produces a 422 — proven by a payload-shape unit test (field absent, not empty
  string).
- The visibility explainer is informational only; no sharing choice is collected here.
- Snapshot matrix {light,dark} × {standard,XXXL} for every named state (idle-empty, idle-filled,
  submitting, error); all strings banned-copy-clean.
- Full iOS suite green with the grown snapshot count.
