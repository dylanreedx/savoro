# P7.2 — Make the live-Worker journey account-real, URL-parameterized, and required at checkpoints

Phase: 7 · Journeys and gates
Track: integration
Execution: **autonomous**
Depends on: P7.1, P1.4, P3.4
Supersedes: OB-43

## Goal
The live journey covers signup→onboarding→log against a real Worker with minted accounts, runs against any base URL, and cannot be skipped at checkpoint gates.

## Context and design direction
Read `_DESIGN.md` and `_RUNBOOK.md` before editing. In
`SavoroIOS/SavoroUITests/SavoroSmokeJourneyTests.swift`, the skip guard is at lines 27–35:
`testLiveTodayAgainstLocalWorkerJourney` is skipped unless `SAVORO_RUN_LIVE_UI_TEST=1` or the
marker file `SavoroIOS/.live-ui-test-enabled` exists, and it hardcodes
`http://127.0.0.1:8787` (line 33) plus `dev-alice-token` (line 34). The journey body is lines
145–188. P3.4 delivered tooling that mints accounts in any onboarding state; P1.4 delivered safe
remote seed tooling — `apps/api/seed/local-dev.sql` (source of `dev-alice-token`) never runs
remotely (locked decision 16). `scripts/preland.sh` exists after P0.3 as the pre-land gate. The
locked decision: the live-Worker journey becomes REQUIRED at checkpoint gates instead of
skipped-by-default. This ticket is deliberately scoped so another fresh agent can verify and land
it independently.

## Files
- `SavoroIOS/SavoroUITests/SavoroSmokeJourneyTests.swift`
- `scripts/preland.sh`

This fence covers the journey and the gate that enforces it; P7.1's mock journeys and any app code
stay untouched.

## Approach
1. Extend the live journey (or add a sibling live test in the same file) to start signed out,
   create an account via the real signup flow, complete onboarding (username → skip targets), and
   log against the Worker — replacing the hardcoded `dev-alice-token` launch injection with an
   account minted by the P3.4 tooling (invoke it from the test runner side or a documented
   pre-step; record which).
2. Parameterize the base URL: read `SAVORO_LIVE_BASE_URL` from the runner environment, defaulting
   to `http://127.0.0.1:8787`, so the identical journey runs against the deployed preview. Keep
   the existing opt-in skip guard for ordinary local runs.
3. In `scripts/preland.sh`, add a `PRELAND_CHECKPOINT=1` branch that runs
   `xcodebuild test … -only-testing:SavoroUITests/SavoroSmokeJourneyTests/<live test>` with
   `SAVORO_RUN_LIVE_UI_TEST=1` exported, and **fails (non-zero) if the test is skipped or red** —
   an XCTSkip at checkpoint is a failure, not a pass. Per-land runs without the flag stay fast and
   unchanged.
4. Policy (document in the script header): per-land = suites + banned-copy grep as today;
   checkpoint gates (P7.3 entry, P8.5 pre-upload) = same plus the live journey, local Worker
   required, deployed-preview run required before any upload.
5. Negative witness: with the Worker down, run the checkpoint-flagged script and record the
   non-zero exit and failing assertion.

## Done when
- The live journey covers signup→onboarding→log using a minted account; `dev-alice-token` no
  longer appears in the test file.
- The same test passes against `http://127.0.0.1:8787` and, base URL swapped via
  `SAVORO_LIVE_BASE_URL`, against the deployed preview from P1.3.
- `PRELAND_CHECKPOINT=1 scripts/preland.sh` runs the live journey and exits non-zero if it is
  skipped or fails; plain `scripts/preland.sh` behavior is unchanged.
- Required negative witness: checkpoint-flagged run with the Worker down exits non-zero — record
  the exact failure.

## Watch out
- Never point a minted-account script at seed SQL: `seed/local-dev.sql` remotely is forbidden
  (locked decision 16). Preview accounts come only from P1.4/P3.4 tooling, printed once, never
  committed.
- `scripts/preland.sh` is authored by P0.3 — if it does not exist or its shape conflicts with this
  packet, mark **blocked** with evidence rather than creating a parallel script.
- Do not weaken the ordinary skip guard for developers' fast local runs; the requirement moves to
  the checkpoint flag, not to every run.
- The old journey asserts seeded fixtures (`live_dev_bowl`, "Dev Burrito Bowl", +520 cal, lines
  159–186). A fresh minted account has none of that — rewrite assertions around the entities the
  journey itself creates; do not keep stale seed expectations.
- If Release/Keychain session flow (P4.6) makes launch-env token injection impossible, that is
  expected — the journey must sign in through the UI, not inject tokens.
