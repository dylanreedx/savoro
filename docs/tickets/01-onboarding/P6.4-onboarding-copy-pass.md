# P6.4 — Run the onboarding copy pass and centralize the copy lint

Phase: 6 · Goal-less mode and Profile
Track: frontend
Execution: **autonomous**
Depends on: P5.8, P6.3
Supersedes: OB-39

## Goal
Review every new P5/P6 string in one calm, non-judgmental, jargon-free voice, and extend the copy
lint so it structurally cannot omit the new surfaces.

## Context and design direction
Read `_DESIGN.md` and `_RUNBOOK.md` before editing. Verified repo fact: there is no single
centralized banned-copy test today — the lint lives as per-surface assertions in
`SavoroIOS/SavoroTests/ScaffoldTests.swift`: the denied-terms list inside
`testPlaceholderFeatureViewsCanBeConstructed` (list at line 119: mock, scaffold, backend,
placeholder, adherence, compliance, failed, over limit, guilt, cheat, bad food),
`testTodayProgressCopyStaysNonShamingNearAndPastGoal` (line 257, shaming-terms list at 268), and
`testVisibleTodayPrivacyAndSupportCopyAvoidsComplianceLanguage` (line 274). Each new P5/P6 screen
shipped its own copy assertion, but nothing forces future surfaces into the lint. This ticket does
two things: a human-quality editorial pass over every new string, and a centralized banned-copy test
built on an exhaustive string registry so omission is a compile/test failure, not a memory. This
ticket is deliberately scoped so another fresh agent can verify and land it independently.

## Files
- `SavoroIOS/Savoro/Features/Onboarding/*.swift` (copy edits only — every P5 screen)
- `SavoroIOS/Savoro/Features/Today/TodayPlaceholderView.swift` (P6.2 goal-less strings, copy edits
  only)
- `SavoroIOS/Savoro/Features/Profile/` (P6.3 screen strings, copy edits only)
- `SavoroIOS/SavoroTests/OnboardingTests.swift` (the new centralized banned-copy test + registry)
- `SavoroIOS/SavoroTests/SnapshotTests.swift` + `SavoroIOS/Scripts/record-snapshots.sh` (ONLY if
  copy edits shift existing P5/P6 references — re-record exactly those, count unchanged)

This fence is words and their lint; do not absorb adjacent work (no layout changes, no logic
changes, no edits to the pre-existing ScaffoldTests lints — they stay as-is and green).

## Approach
1. Inventory: enumerate every user-visible string introduced by P5.1–P5.8 and P6.1–P6.3 (screen by
   screen, from the code, not from packets). Expose them via a testable registry — e.g. each
   onboarding/Profile view model contributes a `visibleCopy: [String]` (the pattern
   `ScaffoldTests.swift:379` already uses) collected by one `OnboardingCopyInventory` in app code.
2. Editorial pass against the voice bar: calm, non-judgmental, zero jargon, invitation over
   instruction, consistent capitalization and terminology (one name for "targets" everywhere, one
   phrasing for privacy). Fix drift in place.
3. Centralized test: one banned-copy test iterates the full inventory against the complete denied
   list (adherence, compliance, failure, failed, over limit, guilt, cheat, bad food, mock, scaffold,
   placeholder, backend jargon, raw-id patterns like `user_`/UUID shapes) — assert non-empty
   inventory per surface so a screen whose registry returns `[]` fails loudly.
4. Make omission structural: the inventory keys off an exhaustive `CaseIterable` enum of new
   surfaces (welcomeAuth, credentials, username, profileBasics, intent, targets, signedOutReturn,
   goallessToday, profileAccount); adding a P5/P6 surface without registering copy fails the count
   assertion.
5. Cross-check the snapshot evidence after edits: if any pinned strings changed, the owning
   references are re-recorded here (count in `record-snapshots.sh` unchanged — this ticket adds no
   states).

## Done when
- Every new P5/P6 visible string appears in the registry — spot-audited by grepping 3 known literals
  per screen and confirming the test sees them.
- The centralized banned-copy test covers all nine surfaces, asserts non-empty copy per surface, and
  is green after the editorial pass.
- Pre-existing lints (`ScaffoldTests.swift:90/257/274`) remain untouched and green; no allowlist was
  added or broadened anywhere.
- Required negative witness: plant "failed" in one new string (e.g. a P5.2 error message) → the
  centralized copy test goes red naming the surface; record the exact red assertion, restore, rerun
  green.
- Full iOS suite green; snapshot references only re-recorded where this ticket's copy edits changed
  pixels.

## Verify
```bash
cd SavoroIOS && xcodebuild test -scheme Savoro -destination 'platform=iOS Simulator,name=iPhone 17'
```
If copy edits shifted references, re-record with `./Scripts/record-snapshots.sh` and list exactly
which images changed and why. Report for the orchestrator's `_LEDGER.md` note: commands + exit
codes, derived test counts, the surface enum's case list, changed-string diff summary, and the
negative-witness red assertion text.

## Watch out
- Banned copy list applies to your OWN replacement strings — an editorial pass that introduces "make
  sure you don't fail" is the classic own-goal.
- Never weaken a gate: do not shrink any existing denied-terms list, do not add an allowlist, do not
  delete per-surface assertions in favor of the central one — the central test is additive.
- Copy edits only: if a better string needs a layout change, note it for a follow-up ticket instead
  of editing geometry.
- Snapshot count in `Scripts/record-snapshots.sh` stays fixed here; only re-record references whose
  strings this ticket changed, and say so explicitly.
- If a locked string (the three intent options, rules copy tied to the backend regex) reads
  awkwardly, it is not yours to change — flag it for Dylan rather than editing; mark blocked only if
  it violates the banned list.
