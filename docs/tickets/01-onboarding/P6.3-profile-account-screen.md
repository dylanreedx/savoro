# P6.3 — Replace the Profile stub with a real account screen

Phase: 6 · Goal-less mode and Profile
Track: frontend
Execution: **autonomous**
Depends on: P6.2, P5.6
Supersedes: OB-38

## Goal
Replace `ProfilePlaceholderView` with a real Profile screen: view/edit current targets (edits POST a
superseding goal), account info, and sign out.

## Context and design direction
Read `_DESIGN.md` and `_RUNBOOK.md` before editing. `Features/Profile/ProfilePlaceholderView.swift`
is verified as a 21-line stub wrapping `PlaceholderFeatureView` with "coming soon" copy. The goals
API is verified in `apps/api/src/routes/goals.ts`: only `GET /current` (lines 14–23) and `POST /`
(lines 25–35) exist — deliberately no PATCH or DELETE — so "editing" targets means POSTing a
complete superseding goal (all four values finite > 0 plus `startDate`, lines 37–69). Reuse P5.6's
`CaloriesFirstTargetsEditor` for the edit surface. Sign out revokes the session via P2.5's logout
endpoint and clears the Keychain through P4.1's SessionStore, returning to the P4.5 signed-out root.
This screen must match the approved design pack in docs/tickets/01-onboarding/design/, post-P0.8.
This ticket is deliberately scoped so another fresh agent can verify and land it independently.

## Approach
1. Build the Profile screen from L-35 primitives per the design pack: current targets section
   (values from `GET /v1/goals/current`; the designed no-goal state shows the same calm add-targets
   affordance as P6.2), account section (username, display name, email where present — never a raw
   id, locked decision 5), and sign out.
2. Targets editing presents P5.6's `CaloriesFirstTargetsEditor` pre-filled from the current goal;
   save POSTs a complete superseding goal with `startDate` = today; on 201 the screen and Today both
   reflect the new goal.
3. Sign out: call the P2.5 logout request (revocation), clear Keychain via SessionStore, transition
   the P4.5 state machine to signed out — in that order; a logout network miss must still clear
   locally (never strand the user signed in).
4. Named states: `targets-set`, `no-targets`, `editing-targets`, `signout-confirm` (if the pack
   specifies confirmation), `loading`, `error`.
5. Unit tests: superseding-goal payload pinned (all four values + startDate, no id, no PATCH verb
   anywhere); sign-out ordering (revoke → clear → transition) with a mock client, including the
   network-miss branch; nil-goal Profile shows no denominators; every visible string
   banned-copy-clean.
6. Snapshot every named state across the full matrix.

## Done when
- Profile shows real current targets (or the designed no-goal state) and real account info with no
  raw ids anywhere.
- Editing targets POSTs a superseding goal — proven by a payload test; nothing in the diff attempts
  PATCH/DELETE on goals.
- Sign out revokes server-side, clears the Keychain, and lands on the signed-out root; the offline
  sign-out branch still clears locally — both tested.
- `ScaffoldTests.swift:90-127` updated coherently: the old stub's constructions/lints replaced by
  the new screen's, with the denied-terms check (line 119) still covering the new strings.
- Snapshot matrix {light,dark} × {standard,XXXL} for every named state; all strings
  banned-copy-clean; full iOS suite green with the grown snapshot count.
