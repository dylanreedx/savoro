# P5.8 — Handle expired sessions with calm signed-out UX

Phase: 5 · Onboarding UI
Track: frontend
Execution: **autonomous**
Depends on: P5.7, P2.6
Supersedes: OB-35

## Goal
A mid-session 401 returns the user calmly to sign-in with no data loss and no crash, and
re-authenticating lands them back in context.

## Context and design direction
Read `_DESIGN.md` and `_RUNBOOK.md` before editing. P2.6 makes the backend enforce session expiry
(and P2.5 revocation) as 401 at the middleware chokepoint; P4.4 gives the iOS client ONE central 401
path that signs the session out. This ticket owns what the user experiences at that moment: the P4.5
state machine transitions to a signed-out-return variant of the welcome screen — recognizably the
P5.1 screen with one added calm line explaining they were signed out for safety and nothing was
lost. Re-auth must return the user to where they were (at minimum, the tab they were on; in-progress
form input preserved where feasible). All P5 screens build ONLY after the P0.8 design verdict and
must match the approved design pack in docs/tickets/01-onboarding/design/. This ticket is
deliberately scoped so another fresh agent can verify and land it independently.

## Files

This fence is the 401 experience plus its evidence; do not absorb adjacent work (the 401 detection
seam itself is P4.4's and must not be reworked here; backend expiry is P2.6's).

## Approach
1. Hook the P4.4 central 401 signal into the P4.5 state machine: capture a lightweight return
   context (selected tab, and any unsent draft the active screen exposes), clear the session via
   P4.1 SessionStore, and present the signed-out-return state.
2. Signed-out-return renders the P5.1 welcome screen plus one calm explanatory line (e.g. "You were
   signed out to keep your account safe. Sign back in to pick up where you left off." — final words
   per the design pack; banned-copy rules are the hard constraint).
3. On successful re-auth of a user whose `onboardingState` is complete, restore the captured context
   (land on the captured tab, re-offer preserved draft input); a different account signing in
   discards the captured context entirely — never leak one user's draft to another.
4. Named state to snapshot: `signedOutReturn` (the welcome screen with the explanatory line), full
   matrix.
5. Unit tests: 401 signal → signedOutReturn transition; captured context survives the transition;
   re-auth same-user restores it; re-auth different-user discards it; no crash when the 401 arrives
   during onboarding itself (route to plain welcome, not signedOutReturn-with-context).
6. Add a copy assertion: the explanatory line is banned-copy-clean (especially no "expired",
   "failed", or "invalid session" jargon).

## Done when
- A stubbed mid-session 401 (URLProtocol or mock client, matching P4.4's test harness) drives the
  app to signedOutReturn without a crash, with the session cleared — unit/integration test proves
  the full transition.
- Re-auth as the same user restores tab context and any preserved draft; a different user gets a
  clean slate — both tested.
- Snapshot matrix {light,dark} × {standard,XXXL} for the signed-out-return state; strings
  banned-copy-clean.
- Required negative witness: disconnect the 401 signal from the state machine (swallow it) → the
  transition test goes red; restore, rerun green, record the exact red assertion.
- Full iOS suite green with the grown snapshot count.

## Watch out
- Banned copy list applies (no failure/failed/guilt/etc.) — "session expired" is backend jargon; say
  what happens next, not what broke.
- Build from L-35 design-system primitives; reuse the P5.1 screen — do not fork a second welcome
  layout.
- Never swallow the 401 to keep a screen alive (runbook: never weaken a gate); the calm UX is
  downstream of an honest signal.
- Draft preservation is best-effort, scoped to what screens already expose — do not build a general
  persistence framework for this ticket.
- Snapshot reference counts in `Scripts/record-snapshots.sh` grow deliberately in this ticket only;
  if P4.4's landed 401 seam differs from the shape assumed here, follow compiled reality and note
  the delta.
