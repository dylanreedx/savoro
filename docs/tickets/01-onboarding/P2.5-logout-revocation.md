# P2.5 — Implement POST /v1/auth/logout with session revocation

Phase: 2 · Backend auth
Track: backend
Execution: **autonomous**
Depends on: P2.4
Supersedes: the logout/revocation half of OB-15

## Goal
Land logout: the presented session is revoked by setting `revokedAt`, and a revoked session 401s immediately at the middleware chokepoint.

## Context and design direction
Read `_DESIGN.md` and `_RUNBOOK.md` before editing. Compiled reality is better than the epic feared: revocation is ALREADY half-built. `sessions.revokedAt` exists (`apps/api/src/db/schema.ts`, line 40), and the single session chokepoint — `findUserIdByToken` in `src/repo/sessions.ts` (lines 7–15), called from `src/middleware/auth.ts` line 16 — already filters `isNull(sessions.revokedAt)` in its query (line 11). What is missing is (a) any way to SET `revokedAt` (nothing in the repo writes it; grep confirms only the seed files touch it, always to null) and (b) any test coverage of the revocation filter. So this ticket adds the write path and pins both directions with tests; it does not need to change the chokepoint's read logic. This ticket is deliberately scoped so another fresh agent can verify and land it independently.

## Files
- `apps/api/src/routes/auth.ts` (logout route)

## Approach
1. Read the approved contract in `docs/api-contract.md` for logout's request/response shape (OB-2 drafted it as session revocation; confirm the approved status code and body).
2. Add `revokeSessionByToken(db, token)` in `src/repo/sessions.ts`: hash the token with `hashToken` (`src/token.ts`) and `UPDATE sessions SET revoked_at = <now ISO> WHERE token_hash = ?` — mirror the ISO-8601 UTC timestamp convention used throughout the file (e.g. lines 9, 19).
3. Route `auth.post('/logout', …)`: read the bearer token from the `Authorization` header (same parsing shape as `src/middleware/auth.ts` lines 12–15) and revoke it. Decide per contract whether logout with a missing/unknown token 401s or succeeds idempotently — follow the approved text; if silent, prefer requiring a valid bearer (mount `requireAuth` or parse+404-free equivalent) and note the choice.
4. Keep revocation by token, not by session id — the client only ever holds the opaque token.
5. Tests in `test/auth-logout.test.ts`, both directions through the REAL middleware (probe: `GET /v1/logs/day?date=2026-06-10` as in `test/auth.test.ts`):
   - before logout: seeded/issued token → 200;
   - logout → contract-specified success response; `revoked_at` is non-null in the DB (raw `env.DB.prepare` check, like `test/auth-apple.test.ts` lines 49–59);
   - after logout: same token → 401 immediately (name it, e.g. `'a revoked session is rejected by the middleware'`);
   - revoking one session leaves the user's OTHER sessions working (issue two tokens via login, revoke one, assert the other still 200s);
   - repeated logout with the already-revoked token behaves per contract (idempotent or 401 — pinned either way).

### Implementation sketch
```ts
// repo/sessions.ts
export async function revokeSessionByToken(db: Db, token: string): Promise<void> {
  const tokenHash = await hashToken(token)
  await db.update(sessions)
    .set({ revokedAt: new Date().toISOString() })
    .where(eq(sessions.tokenHash, tokenHash))
}
// routes/auth.ts — bearer parsing mirrors middleware/auth.ts lines 12–15;
// enforcement stays in findUserIdByToken's existing isNull(revokedAt) predicate.
```

## Done when

- `revokedAt` is written by exactly one repo function; no duplicate revocation filter was added to the middleware — the existing query predicate at `src/repo/sessions.ts` line 11 remains the single enforcement point.
- The 401 for a revoked token is the standard `unauthorized` envelope from `errorResponse` — no new error code.

## Watch out
- Do not re-enforce revocation inside `middleware/auth.ts` — enforcement already lives in the chokepoint query; a second check would mask regressions in the first.
- Revoke by `token_hash`, never by plaintext token comparison against the DB (only hashes are stored — `src/token.ts` line 1 comment).
- Do not revoke ALL of a user's sessions on logout unless the approved contract says so; the drafted semantics revoke the presented session.
- `test/seed.ts`'s `seedUser` inserts sessions without `revoked_at` (line 11) — safe, the column is nullable; extend rather than modify it if you need a revoked fixture.
- If the contract's logout section is missing or contradicts the presented-session semantics, mark blocked quoting `docs/api-contract.md` as landed by P0.8.
