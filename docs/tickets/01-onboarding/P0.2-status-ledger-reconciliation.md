# P0.2 — Reconcile STATUS.md with derived test counts

Phase: 0 · Foundations and contracts
Track: meta
Execution: **autonomous**
Depends on: P0.1
Supersedes: OB-44 (docs/epics/onboarding.md)

## Goal
Make `docs/STATUS.md` stop lying about test counts and its stretch queue, and encode the rule that
counts are always re-derived from runner output.

## Context and design direction
Read `_DESIGN.md` and `_RUNBOOK.md` before editing. Three drift instances are verified against the
repo. First, `docs/STATUS.md` line 200 claims "Backend: 66 → **131 tests** (124 + 7 foods) across 16
files" — but the 7 `foods.test.ts` cases are already inside the 124: counting `it(`/`test(` across
the 16 files in `apps/api/test/*.test.ts` totals exactly 124 (foods contributes 7 of them). Second,
line 201 claims "iOS: 204 → **224 unit/snapshot tests**", but `SavoroIOS/SavoroTests/*.swift`
contains 242 `func test` declarations today (`_RUNBOOK.md` line 32 also records 242 at authoring
time); the runner is authoritative. Third, the stretch queue double-lists four tickets: lines 60–63
record S2b (SAV-133), S3 (L-2), S7b (L-28), and S8b (L-37) as **landed** with commits, while lines
64–70 re-list SAV-133, L-2, L-28, and L-37 as `queued` (rows S2, S3, S7, S8). This ticket is
deliberately scoped so another fresh agent can verify and land it independently.

## Files
- `docs/STATUS.md`

This fence is one documentation file; the fix is reconciliation, not history rewriting, so no code,
test, or queue file changes belong here. Do not absorb adjacent work (P0.3's preland script also
"emits counts" — it is a separate ticket).

## Approach
1. Derive the real counts from runner output, not from grep alone:
   - `cd apps/api && bun run test` — record the vitest total (expected 124 passed).
   - `cd SavoroIOS && xcodebuild test -scheme Savoro -destination 'platform=iOS
     Simulator,name=iPhone 17'` — record the "Executed N tests" total (expected 242 unit/snapshot;
     UI journeys are reported separately).
2. Fix line 200: replace the "131 tests (124 + 7 foods)" claim with the derived backend total,
   without double-counting foods.
3. Fix line 201: replace the stale 224 with the derived iOS total.
4. Deduplicate the stretch queue: remove the `queued` rows that re-list already-landed tickets
   (S2/SAV-133, S3/L-2, S7/L-28, S8/L-37 at lines 64–65 and 69–70); leave the genuinely open rows
   (S4 SAV-72, S5 L-25, S6 L-5) and all landed rows with their evidence intact.
5. Add one rule line near the top of STATUS.md (e.g. under "Health at a glance"): test counts in
   this file are re-derived from runner output on every update and are never to be read back as a
   source of truth — the runner is authoritative.
6. Do not rewrite the historical iteration narrative ("Last run report" entries record what was true
   at the time); only the current-claims surfaces above change.

## Done when
- `docs/STATUS.md` contains no double-counted totals: the backend claim matches a fresh `bun run
  test` total and the iOS claim matches a fresh `xcodebuild test` "Executed N tests" total, both
  recorded from this ticket's own runs.
- No ticket appears in the stretch queue as both **landed** and `queued`.
- The re-derive rule line is present and unambiguous.
- No other section of STATUS.md changed (diff review: every hunk traces to one of the three named
  drift instances or the rule line).

## Watch out
- Counts come from the runner, not from `grep -c` — grep is a cross-check, but the ledger note must
  cite runner output.
- Do not "helpfully" update the Health-at-a-glance per-area numbers (66/66, 204/204) or iteration
  history — those are period records; only the three verified drift instances and the new rule line
  are in scope.
- If a fresh run yields totals different from 124/242 (main moved since authoring), write what the
  runner actually says — never copy the numbers from this packet.
- If either suite is red on clean main, that is a baseline failure: stop and mark this ticket
  blocked with the failing output (`_RUNBOOK.md` stop conditions), rather than reconciling against a
  broken run.
