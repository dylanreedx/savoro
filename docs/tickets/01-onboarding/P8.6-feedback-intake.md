# P8.6 — Convert Checkpoint A UAT feedback into the next ticket wave

Phase: 8 · Checkpoint A
Track: meta
Execution: **autonomous**
Depends on: P8.5

## Goal
Every finding from Dylan's Checkpoint A UAT becomes a fully-formed packet or an explicitly deferred note, so the program closes with zero untracked feedback.

## Context and design direction
Read `_DESIGN.md` and `_RUNBOOK.md` before editing. The P8.5 ledger row holds Dylan's UAT
checklist results verbatim — that row is this ticket's sole input. The epic contract
(`docs/epics/onboarding.md`, OB-50) requires feedback to become new tickets "before Checkpoint B
work starts". Because `_RUNBOOK.md` reserves `_QUEUE.md`/`_LEDGER.md`/packet edits for the
orchestrator, this meta ticket is executed by the orchestrator directly, not dispatched to a
worker. Linear remains blocked (since 2026-07-17), so `docs/backlog-local.md` stays the
cross-program index and must record that Checkpoint A shipped. This ticket is deliberately scoped
so another fresh agent can verify and land it independently — its output is documents in this
directory plus one backlog note.

## Files
- `docs/tickets/01-onboarding/P9.x-*.md` (new packets, one per finding)
- `docs/tickets/01-onboarding/_QUEUE.md` (append-only rows for the new packets)
- `docs/tickets/01-onboarding/_LEDGER.md` (append-only rows; plus this ticket's own row via the orchestrator)
- `docs/backlog-local.md` (Checkpoint A shipped note + any Checkpoint B program pointers)

This fence is program bookkeeping; no application or API code changes belong here, however small a
"quick fix" looks.

## Approach
1. Extract every discrete finding from the P8.5 ledger row: failed bullets, redline-style
   observations, and anything Dylan phrased as "should" or "annoying". One finding = one intake
   item; do not merge.
2. Triage each finding with Dylan's recorded words as the authority:
   - **P9.x packet** — in-scope for this program's surfaces (onboarding, auth, Today, logging,
     Profile): author it in the exact packet format used by P7/P8 packets (Phase/Track/Execution/
     Depends on, Goal, Context and design direction, Files fence, Approach, Done when, Verify,
     Watch out), with verified file:line grounding and named negative witnesses where the fix is
     regression-shaped;
   - **Checkpoint B program item** — belongs to catalog logging, recipes, social, or other parked
     work: record it under the appropriate epic/backlog entry with a pointer, not a P9 packet;
   - **explicitly deferred** — written down with the reason and requiring Dylan's sign-off to
     count as closed.
3. Append the new P9.x rows to `_QUEUE.md` (numbering continues after row 50; dependencies stated)
   and matching `pending` rows to `_LEDGER.md`. Never renumber, reorder, or rewrite existing rows
   in either file.
4. Add the `docs/backlog-local.md` note: Checkpoint A shipped (build, date, TestFlight state), the
   count of P9.x follow-ups, and where the queue lives.
5. Present the finding→disposition table to Dylan; deferred items need his explicit sign-off
   recorded before this ticket is done.

## Done when
- Every UAT finding from the P8.5 ledger row appears exactly once in the disposition table as a
  P9.x packet, a Checkpoint B pointer, or a signed-off deferral — no orphans.
- Each P9.x packet passes the same structural bar as this program's packets (verified references,
  fenced files, verifiable Done-when, Verify commands).
- `_QUEUE.md` and `_LEDGER.md` grew strictly by appended rows — a diff shows zero changed or
  deleted existing lines.
- `docs/backlog-local.md` records that Checkpoint A shipped.
- Dylan's sign-off on the deferral list is recorded in this ticket's ledger note.

## Watch out
- Do not fix anything while filing it — even a one-line copy defect gets a packet; in-gate fixes
  are how supervised evidence rots.
- Append-only is a hard rule: if a finding invalidates an existing pending row, add a superseding
  row/packet and note the relationship — never edit the old row.
- If P8.5 landed with zero failures and zero redlines, this ticket still runs: it writes the
  Checkpoint A shipped note and records "no findings" with Dylan's confirmation.
- Do not migrate anything to Linear (blocked since 2026-07-17; per memory and `_DESIGN.md` §8).
- If a finding contradicts a locked decision (e.g. Dylan asks for fixture data on a live screen),
  do not author a packet that violates the lock — surface the conflict to Dylan and record his
  explicit override or the finding's deferral.
