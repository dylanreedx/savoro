# P4.6 — Make live configuration Release-safe: base URL without tokens

Phase: 4 · iOS auth core
Track: frontend
Execution: **autonomous**
Depends on: P4.5
Supersedes: OB-27

## Goal
Release builds carry a build-configuration base URL and inject sessions only from the Keychain,
retiring the Debug-only env-var seam and the `SAVORO_API_TOKEN` variable entirely.

## Context and design direction
Read `_DESIGN.md` and `_RUNBOOK.md` before editing. Verified today: `AppEnvironment.configured`
(`SavoroIOS/Savoro/App/AppEnvironment.swift:33-50`) requires BOTH `SAVORO_API_BASE_URL` and
`SAVORO_API_TOKEN` process env vars or falls back to mock, and `appLaunchEnvironment` (`:52-60`)
allows live only under `#if DEBUG` — so Release is hard-wired to mock and no TestFlight build has
ever exercised the live path. The current guard test is
`testLaunchEnvironmentFallsBackToMockUnlessCompleteLiveConfigurationIsAllowed`
(`SavoroTests/ScaffoldTests.swift:14-31`; note the spec's "~9-30" also spans the separate
preview-mock test at `:8-12`, which stays). Locked decision 11: Release never carries development
tokens; sessions come only from Keychain after real sign-in (P4.1 `SessionStore`, P4.5 wiring). This
ticket is deliberately scoped so another fresh agent can verify and land it independently.

## Approach
1. Base URL through build configuration: add an Info.plist key (e.g. `SavoroAPIBaseURL`) populated
from an xcconfig/build-setting per configuration (Debug → local Worker default, Release → the
preview HTTPS URL from P1.3). Read it in `AppEnvironment` at launch; validate scheme http(s) + host
as the current code does (`:40-42`). No URL in source-code string literals beyond the Debug default.
2. Session injection: replace `authTokenProvider: { token }` (env-var closure, `:49`) with a
provider that reads P4.1's `SessionStore` (as wired by P4.5). Delete `SAVORO_API_TOKEN` handling
entirely — grep the app target for the string; zero hits when done.
3. Rework `configured`/`appLaunchEnvironment`: live configuration becomes legal in Release (that is
the point), gated on a valid configured base URL — not on env vars. Keep a Debug-only escape hatch
for the local Worker (`SAVORO_API_BASE_URL` env override may remain `#if DEBUG` for the existing
live UI test flow) but it must not exist in Release compilation.
4. Flip the guard test: `ScaffoldTests.swift:14-31` currently asserts Release-equivalent input
yields mock. Replace with Release-must-never-carry-dev-credentials, asserting for a
Release-equivalent environment: (a) no `SAVORO_API_TOKEN` (or any env token) can influence the
client — a poisoned env dictionary still yields a client whose built request has NO Authorization
header until a session exists; (b) the auth token provider resolves only through the session store;
(c) no dev token literal (`dev-alice-token`) ships in the Release path. Update
`testCompleteAllowedLaunchEnvironmentSelectsAuthenticatedLiveClient` (`:33-47`) to the new
construction seam rather than deleting it (never weaken a gate — the request-shape assertions must
survive).
5. Verify the mock/live boundary: `.localMock`/`.preview` (`AppEnvironment.swift:62-63`) and
existing preview-mock assertions (`ScaffoldTests.swift:8-12`) stay intact; distributed builds must
never mix fixture and live surfaces (`_DESIGN.md` §7).

## Done when
- `SAVORO_API_TOKEN` appears nowhere in the app target (grep evidence).
- Release compilation can construct a live `URLSessionAPIClient` from the configured base URL, with
  the token provider backed exclusively by `SessionStore`.
- The flipped guard test passes and still fails when a dev credential sneaks into the Release path.
- The Debug local-Worker override compiles out of Release (`#if DEBUG` verified in the diff).
- Full iOS suite green; request-shape assertions from `:33-47` preserved in updated form.
