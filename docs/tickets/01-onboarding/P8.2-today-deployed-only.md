# P8.2 — Remove fixtures from the runtime path so Today reads only the deployed API

Phase: 8 · Checkpoint A
Track: integration
Execution: **autonomous**
Depends on: P8.1, P4.6
Supersedes: OB-47

## Goal
No distributed screen renders fixture data: static sections and fixture-owned orchestration leave the runtime path, and Release reads only the deployed API.

## Context and design direction
Read `_DESIGN.md` and `_RUNBOOK.md` before editing. Verified fixture seams in
`SavoroIOS/Savoro/App/RootPlaceholderView.swift`: state defaults `dayLog: DayLog = .todayFixture`
(line 281) and `todayGoals: MacroTotals = .todayFixtureGoal` (line 282); a shell-owned
`mockAPIClient = MockAPIClient.localMockSuccessRoutes()` (line 285) used by the fork coordinator
(line 508); and the Today-only live seam `environment.usesLiveTodayAPI` branching at lines 332,
360, 384–397, 430, and 440. `liveTodaySections` is *referenced* at RootPlaceholderView.swift:440
but *defined* as `static let liveTodaySections` in
`SavoroIOS/Savoro/Features/Logging/LogPickerPlaceholderView.swift:170` — a hardcoded picker
section list masquerading as live data. P4.6 replaced the Debug env-var seam
(`App/AppEnvironment.swift`) with Release-safe base-URL configuration plus Keychain sessions.
Locked decisions 11 and 12 govern this ticket. This ticket is deliberately scoped so another fresh
agent can verify and land it independently.

## Files
- `SavoroIOS/Savoro/App/RootPlaceholderView.swift`

This fence removes runtime fixture wiring; it does not redesign screens (P8.3 owns degraded
states) and does not touch tab features beyond their fixture seams.

## Approach
1. Replace the `usesLiveTodayAPI` branch (lines 384–397) and the per-callsite live/mock ternaries
   with the single authenticated environment from P4.6: authenticated app state always uses the
   live client against the configured base URL.
2. Remove `.todayFixture` / `.todayFixtureGoal` as runtime state defaults; Today starts from the
   loading state and populates only from the API. Fixtures move behind `#if DEBUG` preview/test
   factories.
3. Delete the `LogPickerViewModel.liveTodaySections` static (LogPickerPlaceholderView.swift:170)
   from the runtime path — the picker's live content must come from the API (`GET /v1/logs/recents`
   exists); if a picker section has no live source yet, it is honestly absent, not fixture-filled.
4. Remove the shell-owned `MockAPIClient.localMockSuccessRoutes()` (line 285) from runtime;
   surfaces that only worked against `/mock/…` become honestly unavailable or use their live
   endpoints — record which in the ledger.
5. Add the guard: a test asserting no fixture type/factory is reachable from the Release runtime
   graph (compile-gate via `#if DEBUG` scoping on fixture symbols so a Release build re-wiring one
   fails to compile, or an equivalent lint/test that fails on fixture references outside
   previews/tests). Pair it with the P4.6 "Release must never carry dev credentials" guard.
6. Update unit/snapshot tests to inject fixtures explicitly through initializers instead of
   relying on runtime defaults.

## Done when
- No fixture symbol (`todayFixture`, `todayFixtureGoal`, `liveTodaySections`,
  `localMockSuccessRoutes`) is reachable from the Release runtime path; previews and tests keep
  them.
- Authenticated Release reads only the deployed API base URL from P4.6 configuration; no
  `usesLiveTodayAPI`-style per-screen mock/live branch remains.
- Required negative witness: re-wire one fixture into the runtime graph (e.g. restore
  `.todayFixture` as the state default), observe the guard go red (or the Release build fail),
  record the exact failure, restore, rerun green.
- Full iOS suite green; live journey still green via the checkpoint script.

## Watch out
- At no point may a distributed build mix fixture and live data on one screen (`_DESIGN.md` §7);
  partial removal that leaves one fixture section beside live totals is a blocker, not progress.
- P4.5/P4.6 will have already reshaped `RootPlaceholderView` (auth gate, state machine). Line
  numbers above are from program authoring — re-verify every seam against compiled reality first;
  if a named seam is already gone, note it in the ledger instead of hunting ghosts.
- Do not delete fixture files themselves — previews and tests are their sanctioned consumers.
- The fork coordinator and non-Today tabs relying on `/mock/…` must not silently keep a runtime
  mock client; "honestly unavailable" is the fallback, per the product thesis.
- If the guard cannot be made to fail on re-wiring (weak stand-in), it violates
  never-weaken-a-gate — find a mechanism that actually goes red or mark blocked with evidence.
