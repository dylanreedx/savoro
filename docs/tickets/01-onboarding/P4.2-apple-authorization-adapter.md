# P4.2 — Wrap ASAuthorizationController behind an AppleAuthorizing protocol

Phase: 4 · iOS auth core
Track: frontend
Execution: **autonomous**
Depends on: P4.1
Supersedes: OB-23

## Goal
Sign in with Apple is callable through a protocol whose DEBUG mock lets simulator runs and unit
tests exercise the full flow without entitlements, yielding the identity token (and nonce) the
backend exchange needs.

## Context and design direction
Read `_DESIGN.md` and `_RUNBOOK.md` before editing. Verified today: no AuthenticationServices code
exists anywhere in `SavoroIOS` — no entitlements file references Sign in with Apple, and
`Core/Auth/` contains only P4.1's SessionStore files. The backend exchange is `POST /v1/auth/apple`
(`apps/api/src/routes/auth.ts:10-30`): it takes `{ identityToken: String }` and returns `{
sessionToken, user: { id, email, displayName } }` (`apps/api/src/repo/sessions.ts:50-53`). This
ticket produces the credential; the typed exchange request is P4.3 and the UI button is P5.1 —
neither belongs here. This ticket is deliberately scoped so another fresh agent can verify and land
it independently.

## Approach
1. In `Core/Auth/`, define the seam:
   ```swift
   struct AppleAuthorizationResult: Equatable, Sendable {
       let identityToken: String   // raw JWT string for POST /v1/auth/apple
       let nonce: String           // the raw nonce whose SHA256 was sent to Apple
   }
   protocol AppleAuthorizing: Sendable {
       func authorize() async throws -> AppleAuthorizationResult
   }
   ```
2. `LiveAppleAuthorizer: AppleAuthorizing` — generates a cryptographically random nonce, sets
`request.nonce = SHA256(nonce)` on `ASAuthorizationAppleIDRequest` (scopes: none needed beyond
default; backend derives email from the token), drives `ASAuthorizationController` via a
continuation-backed delegate, extracts `credential.identityToken` UTF-8 string, and maps user-cancel
(`ASAuthorizationError.canceled`) to a distinct, calm error case the caller can treat as
non-failure.
3. `MockAppleAuthorizer` under `#if DEBUG`: configurable to return a fixed
`AppleAuthorizationResult` or throw a chosen error, so simulator flows and tests never need
entitlements or Apple servers.
4. Unit tests (`SavoroTests/AppleAuthorizationTests.swift`):
   - nonce generation: two calls produce different, sufficiently long nonces; the hashed value attached
     to the request equals SHA256(raw nonce) — factor hashing into a testable pure function;
   - credential mapping: a nil/empty `identityToken` on the credential maps to a named error, never an
     empty string;
   - mock round-trip: an `AppleAuthorizing`-typed flow using `MockAppleAuthorizer` yields the
     configured token, and the cancel case surfaces as the distinct cancel error.
5. Do not request or wire entitlements, capabilities, or `Info.plist` changes — the physical-device
proof is P8.4's supervised job.

## Done when
- `AppleAuthorizing` + result type exist; the live adapter compiles against AuthenticationServices;
  the DEBUG mock is target-visible to tests and simulator builds.
- The adapter yields identity token + raw nonce; no session, Keychain, or networking code inside it.
- Cancel is distinguishable from failure via the error type (asserted in tests).
- Named tests for nonce hashing, credential mapping, and mock round-trip pass.
- Full iOS suite green; Release builds do not compile the mock (`#if DEBUG` verified by reading the diff).

## Watch out
- Without the Sign in with Apple entitlement, the LIVE adapter cannot succeed on simulator — that is
  expected and is why the mock exists; do not add an entitlements file to force it (P8.4 owns device
  proof).
- If `ASAuthorizationControllerDelegate`'s main-thread requirements fight the async seam, keep the
  continuation bridging inside the live adapter — the protocol stays a plain `async throws` call.
- Send the RAW nonce in the result and the SHA256 to Apple, not the reverse — the backend will
  verify the nonce claim against the raw value when the contract adds it; getting this backwards is
  invisible until P8.4.
- No `displayName`/`fullName` capture flows from Apple here; username and display name come from the
  onboarding pages (locked decision 4).
- If the P0.8-approved auth contract added a nonce field to `POST /v1/auth/apple` that conflicts
  with this shape, follow the contract and note the deviation; if it contradicts the protocol design
  entirely, mark blocked with the contract excerpt.
