# P7.1 — Add onboarding XCUITest journeys with per-step screenshots

Phase: 7 · Journeys and gates
Track: frontend
Execution: **autonomous**
Depends on: P6.4
Supersedes: OB-42

## Goal
Three deterministic XCUITest journeys prove signup, login, and the mock-Apple path end-to-end through onboarding into the goal-less Today, with a screenshot at every step.

## Context and design direction
Read `_DESIGN.md` and `_RUNBOOK.md` before editing. The existing journey suite is
`SavoroIOS/SavoroUITests/SavoroSmokeJourneyTests.swift`. Its screenshot pattern is `capture(_:)`
(verified at lines 228–242): each step is saved BOTH as an `XCTAttachment` with
`.lifetime = .keepAlways` AND as a PNG written to `sourceArtifactDirectory` —
`SavoroIOS/.ui-artifacts/` (gitignored via `SavoroIOS/.gitignore`). Reuse exactly this dual-write
pattern. Note that the existing `setUpWithError` (lines 22–24) deletes the whole `.ui-artifacts/`
directory before every test — your new suite must not inherit that wipe, or later tests destroy
earlier tests' evidence (see Watch out). By P6.4 the onboarding screens (P5.1–P5.8), goal-less
Today (P6.2), root state machine (P4.5), and the P4.2 DEBUG Apple authorization adapter all exist.
This ticket is deliberately scoped so another fresh agent can verify and land it independently.

### Operator redline — approved 2026-08-05

P0.3 adds the internal `SavoroUITests`-module rendered/accessibility audit helper to
`SavoroSmokeJourneyTests.swift` and explicitly records that its coverage is not exhaustive. Call
that same helper directly from the new onboarding journey file; do not copy the denied policy or add
an app-side hook. Expand runtime coverage to every onboarding state reached here. Audit user-facing
labels, values, placeholders, titles, alerts, and buttons; never treat technical accessibility
identifiers as visible copy.

## Approach
1. Read `SavoroSmokeJourneyTests.swift` in full and copy its helper vocabulary (`element`,
   `assertSurface`, `reveal`, `capture`) into the new file, adjusting `capture` to write into a
   suite-specific subdirectory such as `.ui-artifacts/onboarding/` created (not wiped) in setup.
2. Discover the deterministic launch seam the P4.5/P5.x work established for driving auth screens
   against mocks (launch environment or launch argument; check `App/SavoroApp.swift`,
   `App/AppEnvironment.swift`, and existing UI-test launch code as they exist post-P6.4). Use it —
   do not invent a second seam.
3. Journey A — email signup: welcome/auth → email signup form → username page → skip targets →
   land on the goal-less Today (assert no ring denominator, no progress copy). `capture` each step.
4. Journey B — login: an existing (mock-seeded) account signs in and lands on Today, skipping
   onboarding. `capture` each step.
5. Journey C — mock Apple: drive the P4.2 DEBUG adapter's mock authorization path through the same
   username page and into Today. `capture` each step.
6. Navigate with accessibility identifiers, not copy that the editorial pass may reword. At every
   captured surface, run the P0.3 rendered-copy audit against user-facing labels, values,
   placeholders, titles, alerts, and buttons. Exclude technical identifiers, and name the journey,
   step, element type, and offending rendered value on failure.
7. Cover normal onboarding states in all three journeys plus each loading/error state that the
   deterministic seam can reach. Record any state that remains outside runtime coverage; source and
   snapshot gates remain additive.
8. Run the full iOS suite plus the new journeys; confirm every PNG landed in the artifacts dir.

## Done when
- All three journeys pass deterministically (no network, no local Worker) on the standard
  simulator destination, alongside the existing suites — nothing removed or weakened.
- Every step in each journey produces both an `XCTAttachment` and a PNG under
  `SavoroIOS/.ui-artifacts/onboarding/`, named with a numbered step prefix.
- Journey A ends on the goal-less Today with an explicit assertion that no progress/denominator
  element exists.
- Every captured onboarding surface passes the rendered-copy audit; a scratch-only denied-value
  witness makes that audit fail with the exact journey/step/value before restoration.
- The ledger states which loading/error states were exercised and the honest runtime coverage limit.
- Live-Worker variants are NOT added here — they belong to P7.2.

## Watch out
- The existing `setUpWithError` wipes `.ui-artifacts/` per test (lines 22–24). Do not copy that
  wipe into the new suite; create your subdirectory idempotently so evidence accumulates.
- If no deterministic launch seam exists for reaching the signed-out state in UI tests (i.e. P4.5/
  P5.x shipped without one), mark this packet **blocked** with the evidence (file+line of the root
  boot path) instead of adding app code — app-side hooks are outside this fence.
- Fixtures serve previews/tests only (locked decision 12): the journeys may rely on mock/DEBUG
  seams, but must not assert fixture data on screens that P8.2 will later make live-only in ways
  that would force P8.2 to weaken these tests. Prefer structural assertions over fixture values.
- Do not touch `SavoroSmokeJourneyTests.swift`; its skip guard and live journey are P7.2's fence.
- Banned copy applies to test-visible strings too. Plant denied witness text only in a scratch copy;
  do not put it in live attachment names or weaken the P0.3 runtime scanner.
- If the compiled reality conflicts with this packet (screen order, identifiers), follow the
  compiled reality and note the delta in the ledger; if it conflicts with a locked decision, mark
  blocked with evidence.
