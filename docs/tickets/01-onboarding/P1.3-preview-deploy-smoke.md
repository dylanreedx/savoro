# P1.3 — Deploy the Worker to preview and smoke-test it

Phase: 1 · Preview infrastructure
Track: backend
Execution: **autonomous**
Depends on: P1.2
Supersedes: OB-8

## Goal
Deploy the API Worker to the Cloudflare preview environment over HTTPS and prove health, auth rejection, and migration state with recorded curl transcripts.

## Context and design direction
Read `_DESIGN.md` and `_RUNBOOK.md` before editing. After P1.2, Wrangler is authenticated and the preview D1 is real and migrated. The health route exists at `apps/api/src/index.ts` line 27 (`app.get('/health', (c) => c.json({ status: 'ok' }))`) and returns `{"status":"ok"}` (also documented in `apps/api/README.md`). Every `/v1/logs`, `/v1/goals`, `/v1/me` route sits behind `requireAuth` (`apps/api/src/middleware/auth.ts`), which returns the `{ error: { code: 'unauthorized', ... } }` envelope with status 401 when no bearer token is presented — `GET /v1/logs/day?date=...` is the canonical probe used by `test/auth.test.ts`. The deploy command lands in P1.1 as a package script (expected `deploy:preview`, wrapping `wrangler deploy --env preview`; today's pre-split script is `deploy` at `apps/api/package.json` line 7). This ticket is deliberately scoped so another fresh agent can verify and land it independently.

## Files
- `docs/deploy-runbook.md` (record the deployed preview URL and the smoke transcript procedure)

Deploy + evidence only; no `src/`, config, or test changes belong here — if the deploy exposes a code bug, that is a new ticket, not scope creep.

## Approach
1. Verify preconditions: `bunx wrangler whoami` succeeds; `env.preview.d1_databases[0].database_id` in `apps/api/wrangler.jsonc` is a real UUID, not a placeholder. If either fails, mark blocked (P1.2 incomplete).
2. Deploy: `bun run deploy:preview` (verify the exact script name in `apps/api/package.json`; fall back to `bunx wrangler deploy --env preview`). Capture the workers.dev URL from the output.
3. Smoke over HTTPS, capturing full transcripts (`curl -si`):
   - `GET <url>/health` → 200, body `{"status":"ok"}`.
   - `GET <url>/v1/logs/day?date=2026-06-10` with no Authorization header → 401, body `{"error":{"code":"unauthorized","message":"Missing bearer token."}}`.
   - `GET <url>/v1/logs/day?date=2026-06-10` with `Authorization: Bearer not-a-real-token` → 401 (`Invalid or expired session token.`).
4. Compare migration state: `bunx wrangler d1 migrations list DB --env preview --remote` vs `... --local` — both report no unapplied migrations, same highest-numbered file (`0011_foods.sql` at authoring time; verify against `apps/api/migrations/`).
5. Record the preview URL in `docs/deploy-runbook.md` and file the transcripts as ledger evidence.

### Implementation sketch
```bash
# Expected transcript shapes (status lines are the assertions):
curl -si https://<preview>/health
#   HTTP/2 200
#   {"status":"ok"}
curl -si 'https://<preview>/v1/logs/day?date=2026-06-10'
#   HTTP/2 401
#   {"error":{"code":"unauthorized","message":"Missing bearer token."}}
curl -si 'https://<preview>/v1/logs/day?date=2026-06-10' -H 'Authorization: Bearer not-a-real-token'
#   HTTP/2 401
#   {"error":{"code":"unauthorized","message":"Invalid or expired session token."}}
```

## Done when
- The Worker is reachable over HTTPS at a workers.dev (or configured) preview URL.
- `GET /health` returns 200 `{"status":"ok"}`.
- An unauthenticated request to a protected route returns 401 with the `unauthorized` error envelope — this is the required negative witness for the deployed auth chokepoint. Required negative witness: the no-token curl transcript showing 401 is mandatory ledger evidence; a smoke that only checks `/health` is not done.
- Remote migration state matches local (same applied set, none pending).
- `seed/local-dev.sql` was never applied remotely; the preview DB contains no `dev-alice-token` session (spot-check: the invalid-token curl above 401s, and no seed command appears in the transcript).

## Verify
```bash
cd apps/api
bun run deploy:preview
curl -si https://<preview-url>/health
curl -si 'https://<preview-url>/v1/logs/day?date=2026-06-10'
curl -si 'https://<preview-url>/v1/logs/day?date=2026-06-10' -H 'Authorization: Bearer not-a-real-token'
bunx wrangler d1 migrations list DB --env preview --remote
bunx wrangler d1 migrations list DB --local
```
Record in `_LEDGER.md`: preview URL, all four transcripts verbatim, and the matching migration listings.

## Watch out
- Never run `db:seed:local`-style commands with `--remote` or `--env preview`; `seed/local-dev.sql` carries a known dev token and is locked to local by `_DESIGN.md` decision 16. Remote seeding waits for P1.4.
- If the deploy fails on the D1 binding, the P1.1/P1.2 config is wrong — mark blocked with the wrangler error verbatim; do not hand-edit database ids to make it pass.
- The deployed Worker has no `APPLE_IDENTITY_VERIFIER` binding (that is a test-only injection seam, `apps/api/src/routes/auth.ts` line 20), so `POST /v1/auth/apple` on preview exercises the real verifier — do not smoke it with fake tokens and expect anything but 401.
- Do not weaken a smoke check to pass (e.g. accepting 404 where 401 is specified — 404 would mean routing is broken).
- If compiled reality differs (health route moved, script renamed), follow the repo and note the delta; if the preview env is missing entirely, mark blocked.
