## Approach
1. Pre-upload gate: run `PRELAND_CHECKPOINT=1 scripts/preland.sh` — the live journey against the
   local Worker AND a deployed-preview run are both required before any upload (P7.2 policy).
2. Increment the build number (`CURRENT_PROJECT_VERSION` 1 → 2; keep `MARKETING_VERSION 0.1.0`
   unless Dylan says otherwise) in `SavoroIOS/Savoro.xcodeproj/project.pbxproj`.
3. Sanity-check the Release product before upload: preview base URL configured, no
   `SAVORO_API_TOKEN`/dev-token strings in the binary, Sign in with Apple entitlement present
   (from P8.4).
4. Dylan archives and uploads following `SavoroIOS/TestFlightChecklist.md` (Xcode → Archive →
   Distribute → TestFlight internal group), noting where the checklist's mock-mode assumptions no
   longer apply — record the deltas.
5. Dylan's UAT on his iPhone, fresh install from TestFlight (delete any prior build first):
   - create an **email/password** account; complete the FULL onboarding path (username, profile
     basics, intent, targets);
   - manual-log a food; relaunch the app; the session AND the logged day persist;
   - sign out; create/sign in with the **Apple** account; take the SKIP path (no targets); land in
     the goal-less Today; manual-log; relaunch; persists;
   - second-account isolation: neither account can see the other's logs, goals, or profile data;
   - reinstall the app: sign back in; server-side data is intact and onboarding does not replay.
6. Record every checklist item's outcome in the ledger; each failure becomes P8.6 intake material.

  L-36); do not re-derive a different answer ad hoc.

  Dylan's behalf, and P8.6 dispatches only after his verdict is in the ledger.
