# P0.3 — Build the pre-land verification script

Phase: 0 · Foundations and contracts
Track: meta
Execution: **autonomous**
Depends on: P0.2
Supersedes: OB-45 (docs/epics/onboarding.md)

## Goal
A `scripts/preland.sh` the orchestrator runs before every land: both suites, a compiler-backed
banned-copy scanner, derived test counts, and non-zero exit on any failure.

## Context and design direction
Read `_DESIGN.md` and `_RUNBOOK.md` before editing. `_RUNBOOK.md` lines 101–102 already promise this
script's behavior ("wraps both suites plus the banned-copy grep and emits derived test counts"), so
the runbook needs no edit — only the script is missing. The banned-copy list is defined in
`docs/loop-protocol.md` lines 47–49: adherence, compliance, failure, failed, over limit, guilt,
cheat, bad food, plus raw IDs / `mock` / `scaffold` jargon in visible copy. An existing in-suite
enforcement point to mirror: `SavoroIOS/SavoroTests/ScaffoldTests.swift` line 3407,
`testAllViewCodeStringLiteralsAvoidBannedCopyJargonAndRawIdentifiers`, with its denied-terms list at
lines 3409–3413 and raw-id regex `(?i)(recipe_|version_|fork_|user_|\bv\d{6,}\b)` at lines
3414–3416. The pre-land scanner is a belt-and-suspenders repo-level check over app-target string literals, not
a replacement for that test. This ticket is deliberately scoped so another fresh agent can verify
and land it independently.

### Operator redline — approved 2026-08-03

Dylan approved expanding the original single-Bash-file fence after two clean attempts and one
targeted repair demonstrated that an ad-hoc Bash/Perl quote scanner cannot safely own complete
Swift literal semantics. Preserve the strict visible-copy acceptance. Move syntax extraction to a
helper backed by the installed Swift compiler parser (preferred: `xcrun swiftc -frontend
-dump-parse -dump-ast-format json`) or an equivalently real Swift parser. Do not narrow acceptance
to the existing XCTest regex and do not accept known false negatives.

## Approach
1. Write a bash script (`set -euo pipefail`) that accepts an optional repo-root argument, defaulting
   to the root resolved from the script's own location. The argument exists so the negative witness
   can run against a scratch copy.
2. Stage 1 — API: `cd "$ROOT/apps/api" && bun run test && bun run typecheck`. Capture the vitest
   summary line and parse the passed-test total.
3. Stage 2 — iOS: `cd "$ROOT/SavoroIOS" && xcodebuild test -scheme Savoro -destination 'platform=iOS
   Simulator,name=iPhone 17'`. Capture the "Executed N tests" total.
4. Stage 3 — banned copy: invoke the helper over `"$ROOT/SavoroIOS/Savoro"` `*.swift` files (app
   target only — not tests, which legitimately name the banned terms). A real Swift parser owns
   literal/token boundaries; the helper must not hand-tokenize quotes as its source of truth. Scan
   parsed visible string content, case-insensitively, for `adherence`, `compliance`, `failure`,
   `failed`, `over limit`, `guilt`, `cheat`, `bad food`, `mock`, `scaffold`, and raw-id patterns
   `recipe_|version_|fork_|user_|\bv\d{6,}\b`. Cover standard, raw-delimiter, multiline, and
   interpolated literals (including string literals nested inside interpolation). Emit every hit as
   exact file:line plus term/content. Parser/helper failure is a stage failure.
5. Keep syntax extraction separate from presentation policy. No filename, variable-name, prefix,
   enum, JSON/payload, directory, or line-level blanket exemption may hide visible copy. Any narrow
   non-presentational classification must be proved from parser context and covered by a focused
   passing fixture. A legitimate existing hit is a finding to report, not an allowlist-growth excuse.
6. Add deterministic helper/count fixtures under `scripts/preland/` that run without the expensive
   product suites. Required red cases: raw delimiter, nested interpolation, multiline prose with a
   quoted colon token, visible `/mock`, and failed-unit-suite output followed by UI-suite output.
   Keep ordinary non-visible technical literals as explicit green fixtures where parser context
   proves they are not presented.
7. Final output: a summary block with both derived counts and per-stage pass/fail; exit non-zero if
   any stage failed (run all stages before exiting so one report shows everything, but never mask a
   failure).

## Done when
- `bash scripts/preland/tests/run.sh` (or the helper's equivalently named focused runner) proves all
  required syntax and count fixtures, including the five red cases above, and exits 0.
- `bash scripts/preland.sh` on clean main runs all three stages, prints derived counts matching the
  runners (124 API / 242 iOS at authoring time — trust the runner, not this packet), and exits 0.
- Any suite, parser, helper, count-parser, traversal, or banned-copy failure produces a non-zero exit
  and names the failing stage; failed-suite summaries still report the correct derived total.
- Required negative witness: a banned word planted inside a user-facing `.swift` string literal in a
  scratch copy of the repo observed red — script exits non-zero at the banned-copy stage (and/or the
  copy test) with the exact planted file:line output — then the scratch copy is discarded and the
  script rerun green against the live tree.

## Watch out
- Never plant banned words in the live tree — the witness runs only against a scratch-directory
  copy.
- The scanner must not inspect test files or code identifiers, and must not miss real app copy:
  parsed string content in `SavoroIOS/Savoro` is the boundary. If a legitimate existing visible
  literal trips the scanner, that is a finding to report, not an excuse to allowlist it (never weaken
  a gate — `_RUNBOOK.md`).
- Do not edit `_RUNBOOK.md`, `docs/loop-protocol.md`, or any app/app-test file — the script/helper
  mirrors them; focused helper fixtures stay under `scripts/preland/`.
- Do not add a network-fetched parser dependency when the installed Swift compiler parser can supply
  the syntax tree. If that compiler interface proves unusable, stop and report rather than falling
  back to another ad-hoc quote scanner.
- Do not skip or soften a stage to make the script fast (e.g. `-only-testing`); the orchestrator
  relies on this being the full pre-land gate.
- If the banned-term list in `docs/loop-protocol.md` lines 47–49 differs from what this packet
  lists, the protocol file wins — copy from the file, and note the discrepancy in the report.
