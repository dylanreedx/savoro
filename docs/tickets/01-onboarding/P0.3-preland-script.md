# P0.3 — Build the pre-land verification script

Phase: 0 · Foundations and contracts
Track: meta
Execution: **autonomous**
Depends on: P0.2
Supersedes: OB-45 (docs/epics/onboarding.md)

## Goal
A `scripts/preland.sh` the orchestrator runs before every land: both suites, the banned-copy grep,
derived test counts, non-zero exit on any failure.

## Context and design direction
Read `_DESIGN.md` and `_RUNBOOK.md` before editing. `_RUNBOOK.md` lines 101–102 already promise this
script's behavior ("wraps both suites plus the banned-copy grep and emits derived test counts"), so
the runbook needs no edit — only the script is missing. The banned-copy list is defined in
`docs/loop-protocol.md` lines 47–49: adherence, compliance, failure, failed, over limit, guilt,
cheat, bad food, plus raw IDs / `mock` / `scaffold` jargon in visible copy. An existing in-suite
enforcement point to mirror: `SavoroIOS/SavoroTests/ScaffoldTests.swift` line 3407,
`testAllViewCodeStringLiteralsAvoidBannedCopyJargonAndRawIdentifiers`, with its denied-terms list at
lines 3409–3413 and raw-id regex `(?i)(recipe_|version_|fork_|user_|\bv\d{6,}\b)` at lines
3414–3416. The script's grep is a belt-and-suspenders repo-level check over app-target string
literals, not a replacement for that test. This ticket is deliberately scoped so another fresh agent
can verify and land it independently.

## Files
- `scripts/preland.sh` (new; `scripts/` exists after P0.1)

This fence is a single new script. `_RUNBOOK.md` already references `scripts/preland.sh` — appending
a usage note there is explicitly NOT allowed. Do not absorb adjacent work (STATUS.md numbers are
P0.2; the program guard is P0.1).

## Approach
1. Write a bash script (`set -euo pipefail`) that accepts an optional repo-root argument, defaulting
   to the root resolved from the script's own location. The argument exists so the negative witness
   can run against a scratch copy.
2. Stage 1 — API: `cd "$ROOT/apps/api" && bun run test && bun run typecheck`. Capture the vitest
   summary line and parse the passed-test total.
3. Stage 2 — iOS: `cd "$ROOT/SavoroIOS" && xcodebuild test -scheme Savoro -destination 'platform=iOS
   Simulator,name=iPhone 17'`. Capture the "Executed N tests" total.
4. Stage 3 — banned copy: grep string literals in `"$ROOT/SavoroIOS/Savoro"` `*.swift` files (app
   target only — not tests, which legitimately name the banned terms) for, case-insensitively:
   `adherence`, `compliance`, `failure`, `failed`, `over limit`, `guilt`, `cheat`, `bad food`,
   `mock`, `scaffold`, and the raw-id patterns `recipe_|version_|fork_|user_|\bv\d{6,}\b`. Restrict
   matching to quoted string literals so identifiers like `loadFailed` in code (not copy) don't
   false-positive; print every hit with file:line.
5. Final output: a summary block with both derived counts and per-stage pass/fail; exit non-zero if
   any stage failed (run all stages before exiting so one report shows everything, but never mask a
   failure).

## Done when
- `bash scripts/preland.sh` on clean main runs all three stages, prints derived counts matching the
  runners (124 API / 242 iOS at authoring time — trust the runner, not this packet), and exits 0.
- Any stage failure produces a non-zero exit and names the failing stage.
- Required negative witness: a banned word planted inside a user-facing `.swift` string literal in a
  scratch copy of the repo observed red — script exits non-zero at the banned-copy stage (and/or the
  copy test) with the planted file:line in the output — then the scratch copy is discarded and the
  script rerun green against the live tree.

## Verify
```bash
bash scripts/preland.sh
echo "exit: $?"
```
Record in `_LEDGER.md`: the summary block (both derived counts), exit code 0, and the negative
witness's exact red output line.

## Watch out
- Never plant banned words in the live tree — the witness runs only against a scratch-directory
  copy.
- The grep must not be so broad it flags test files or code identifiers, and must not be so narrow
  it misses real copy: string literals in `SavoroIOS/Savoro` is the boundary. If a legitimate
  existing literal trips the grep, that is a finding to report, not an excuse to allowlist it (never
  weaken a gate — `_RUNBOOK.md`).
- Do not edit `_RUNBOOK.md`, `docs/loop-protocol.md`, or any test file — the script mirrors them; it
  does not restate them somewhere new.
- Do not skip or soften a stage to make the script fast (e.g. `-only-testing`); the orchestrator
  relies on this being the full pre-land gate.
- If the banned-term list in `docs/loop-protocol.md` lines 47–49 differs from what this packet
  lists, the protocol file wins — copy from the file, and note the discrepancy in the report.
