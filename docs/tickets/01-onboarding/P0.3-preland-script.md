# P0.3 — Build the bounded pre-land verification gate

Phase: 0 · Foundations and contracts
Track: meta
Execution: **autonomous**
Depends on: P0.2
Supersedes: OB-45 (docs/epics/onboarding.md)

## Goal
A `scripts/preland.sh` the orchestrator runs before every land: both full suites, derived test counts,
a compiler-backed no-growth source-copy gate, and representative rendered/accessibility copy proof.
The gate fails closed inside its declared boundary without claiming sound arbitrary whole-program
Swift dataflow.

## Context and design direction
Read `_DESIGN.md` and `_RUNBOOK.md` before editing. `_RUNBOOK.md` already promises this script's
suite/count behavior. The product rule in `docs/loop-protocol.md` remains strict: user-visible copy
must not contain adherence/compliance/shaming terms, raw identifiers, `mock`, `scaffold`, or backend
jargon. The app also contains legitimate technical route, fixture, payload, accessibility-identifier,
and raw-ID literals, so rejecting every app literal is not baseline-green.

The existing XCTest in `SavoroIOS/SavoroTests/ScaffoldTests.swift` is additive evidence, not the
source scanner's parser. Existing snapshot matrices and `SavoroSmokeJourneyTests` are the runtime
seams to reuse.

### Operator redline — approved 2026-08-05

Dylan approved reopening this row before downstream work with a bounded two-layer contract after
three parser-backed candidates demonstrated that syntax heuristics cannot prove arbitrary aliases,
closures, decoded payloads, helper calls, or cross-file presentation. Preserve the product rule, but
make the proof boundary explicit:

1. compiler-backed syntax extraction plus direct, compiler-visible presentation/technical boundaries;
2. a reviewed locked migration baseline that cannot grow;
3. representative rendered/accessibility scanning in the existing UI journey;
4. explicit honest limits and later migration ownership in P6.4/P7.1.

Indirect whole-program reachability outside that boundary is **not** an acceptance criterion for this
ticket and must not be approximated with filename, variable-name, enum, switch, dictionary, JSON,
metadata, route, or payload heuristics. Unknown new flow fails; existing unresolved source flow may
survive only as an exact reviewed baseline entry assigned to P6.4. P7.1 expands representative
runtime coverage; it does not own source-baseline suppression.

## Enforcement contract

### 1. Explicit app boundaries

Add small compiler-visible types or constructors in `SavoroPrimitives.swift`, equivalent to:

```swift
SavoroVisibleCopy("...")
SavoroTechnicalString("...", kind: .route) // id, route, payload, fixture, accessibilityIdentifier
```

Names may differ only if the focused tests and helper use one unambiguous spelling. These are
boundary markers, not an allowlist:

- a literal assigned to `SavoroVisibleCopy` is always checked;
- a technical wrapper may classify only its own parsed literal in non-presentational use;
- the exact SwiftUI `.accessibilityIdentifier(...)` API is also parser-proven technical context;
  `.accessibilityLabel` and `.accessibilityValue` remain visible sinks;
- converting a technical wrapper into a direct presentation sink does not suppress the sink;
- all other pre-existing technical classifications require an exact manually reviewed baseline
  entry; the helper may not infer them from a filename, directory, identifier, argument label, enum
  case, switch subject, or surrounding dictionary/JSON shape.

P6.4 owns migration of P5/P6 copy producers to the visible boundary. Existing code is not mass
rewritten here.

### 2. Compiler-backed source layer

Use the installed Swift compiler parser (`xcrun swiftc -frontend -dump-parse -dump-ast-format json`)
or an equivalently real already-installed Swift parser. No network dependency and no Bash/Perl
quote tokenizer may own literal boundaries.

Parse every `SavoroIOS/Savoro/**/*.swift` file and:

- extract standard, raw-delimiter, multiline, and interpolated literals, including nested and split
  interpolation;
- emit exact relative file, line, column, denied term/pattern, and parsed content for every finding;
- fail on parse, traversal, extraction, unreadable-subtree, or duplicate-location errors;
- scan case-insensitively using the protocol's product terms and raw-ID/implementation patterns;
- compose statically knowable interpolation segments before matching;
- inspect direct presentation sinks: `Text`, visible `Label`/`Button` titles, `navigationTitle`,
  `alert`, `confirmationDialog`, text-field prompts, accessibility labels/values, the explicit
  visible boundary, and existing design-system constructors whose title/subtitle/detail parameters
  are rendered;
- fail any new dynamic/unknown direct-sink expression unless it is an exact locked legacy entry;
- reject a denied literal in a presentation sink even when nested in a technical wrapper.

Do not attempt arbitrary transitive flow. A reviewer must test the declared boundary, not invent a
claim that the packet explicitly does not make.

### 3. Locked migration baseline

Check in a deterministic manifest under `scripts/preland/` with schema/version and sorted entries.
Each entry records at least:

```text
relative path | line | column | expression/literal SHA-256 | classification | owner | reason
```

Allowed classifications are named technical categories (`id`, `route`, `payload`, `fixture`,
`accessibilityIdentifier`) and `legacy-dynamic-sink`. Requirements:

- exact source location and hash must match; line movement or content drift fails;
- the initial baseline entry itself is the reviewed authority for a legacy classification; the
  helper must not reproduce that judgment with contextual name/label heuristics;
- every entry has a concrete reason and owner (`P6.4` for whole-app source/copy-boundary migration);
  P7.1 expands rendered-journey coverage without adding source-baseline entries;
- a denied literal proven to be directly visible can never enter the baseline;
- the initial manifest is a migration inventory, explicitly not compliance evidence;
- after P0.3 lands, compare against the committed manifest and reject every added entry; removals are
  allowed, replacements/additions are not;
- include a pinned initial count and manifest hash so bootstrap cannot silently regenerate itself;
- stale entries fail, duplicate entries fail, sorting drift fails, and baseline parsing fails closed.

### 4. Representative runtime layer

Extend the existing deterministic UI journey; do not create another launch seam. Define one
internal test-target helper (for example `SavoroRenderedCopyAudit`) at file scope in
`SavoroSmokeJourneyTests.swift`. It accepts `XCUIElement` roots plus a surface/step name and scans
rendered accessibility `label`, user-facing `value`, and placeholder/title text for the same denied
terms and raw-ID shapes. Technical `identifier` fields are deliberately excluded. Use it at Today,
Cookbook, Discover, Community, Profile, Log Picker, Recipe Detail, and Recipe Editor, naming the
surface and offending rendered value on failure. Because the helper is internal to the
`SavoroUITests` module, P7.1's separately registered journey file can call the same helper directly;
no app-side hook, second policy, or project-file edit is needed in P0.3.

Preserve the existing screenshot attachments/PNGs and manually inspect the resulting artifacts.
The full existing snapshot matrix (light/dark × standard/XXXL where owned) and UI journey run as part
of the full iOS suite. This proves only the visited routes/states; it does not prove every runtime
path, and the ledger must say so.

## Orchestration and output

1. `scripts/preland.sh` uses `set -euo pipefail`, accepts an optional repo-root argument, and resolves
   its own repo by default so witnesses can run in scratch copies.
2. Stage 1 — API: run `bun run test && bun run typecheck`; derive the API passed-test total from the
   runner's final summary.
3. Stage 2 — iOS: run the complete `xcodebuild test -scheme Savoro -destination
   'platform=iOS Simulator,name=iPhone 17'`; derive the unit/snapshot total and preserve UI results.
4. Stage 3 — source/baseline: run the compiler-backed helper across the app target and validate
   baseline integrity/no-growth.
5. Run all stages even after one fails. A failed unit summary followed by UI output must not replace
   the failed unit count or status.
6. Print one final block containing each stage PASS/FAIL, API and iOS derived counts, runtime UI
   result, baseline current/locked counts, and `Overall: PASS|FAIL`; exit non-zero if anything failed.

## Focused fixtures

`scripts/preland/tests/run.sh` must run without product suites and cover at least:

**Red:** raw delimiter; multiline quoted-colon prose; nested interpolation; a denied term split
across interpolation segments; visible `/mock`; dictionary/decoded value used directly in a sink;
enum raw value used directly in a sink; `switch request.path` result used directly in a sink;
metadata-labelled value used directly in a sink; technical wrapper converted directly to visible
copy; unknown dynamic sink not in baseline; new baseline entry; stale/hash-mismatched/duplicate or
unsorted baseline; unreadable descendant/parser failure; failed unit output followed by UI output.

**Green:** ordinary calm visible copy; IDs/routes/payload/fixture/accessibility identifiers in their
explicit technical boundary and not presented; every locked baseline entry matching exactly; correct
API/iOS count extraction.

Fixtures prove only the declared syntactic boundary. Do not resurrect whole-program alias fixtures as
if they were sound reachability proof.

## Done when
- `bash scripts/preland/tests/run.sh` exits 0 with every named fixture.
- Boundary tests added to `ScaffoldTests.swift` compile and pass without removing or weakening any
  existing test/list/count.
- The full UI journey audits all eight named representative surfaces and preserves its screenshot
  artifacts.
- `bash scripts/preland.sh` on live main runs all stages, reports runner-derived counts (trust the
  runners), baseline counts, every stage result, and `Overall: PASS`, then exits 0.
- Independent review inspects every initial baseline entry and confirms no directly visible denied
  literal is inventoried.
- Required source witness in a scratch repo: plant denied copy in a direct visible string; focused
  source stage exits non-zero with exact file:line:column and term/content.
- Required boundary witness in scratch: pass a technical wrapper into a direct visible sink; source
  stage exits non-zero.
- Required no-growth witness in scratch: add a syntactically valid baseline entry; baseline stage
  exits non-zero naming growth.
- Required runtime-policy witness in scratch: change the UI-test audit's safe synthetic value to a
  denied rendered value and run only that audit test; it fails naming the value/surface.
- Discard every scratch tree, rerun the complete live `bash scripts/preland.sh` green, and preserve
  exact red and green evidence ordering.

## Honest limits
- This gate does not prove arbitrary transitive presentation across aliases, closures, decoded
  models, helper calls, or files.
- The locked baseline preserves reviewed source migration debt until P6.4 removes it; it is not
  evidence that those flows are safe. P7.1 separately expands runtime route/state coverage.
- Runtime scanning covers the named representative routes/states and accessibility-exposed values,
  not every route or pixel.
- Snapshot images still require human/agent image inspection; source parsing is not visual proof.

## Watch out
- Never plant witnesses in the live tree.
- Never add or replace a baseline entry after bootstrap; fix or remove the source finding.
- Never classify from labels such as `metadata`, `mock`, `route`, or `payload`; use the explicit
  boundary or an exact reviewed legacy entry.
- Never shrink suites, test counts, snapshot modes, surfaces, denied terms, raw-ID patterns, runtime
  fields, fixtures, or negative witnesses.
- Never fetch a parser dependency or fall back to ad-hoc quote scanning.
- Never edit feature files to make the initial baseline easier; source migration is owned by P6.4
  and runtime expansion by P7.1.
