# P4.4 — Put URLSessionAPIClient.send under URLProtocol tests and centralize 401

Phase: 4 · iOS auth core
Track: frontend
Execution: **autonomous**
Depends on: P4.3
Supersedes: OB-25

## Goal
The real HTTP send path gets its first test coverage via a URLProtocol stub harness, decodes the
server error envelope, and routes every 401 through one central signed-out handler.

## Context and design direction
Read `_DESIGN.md` and `_RUNBOOK.md` before editing. Verified today: `URLSessionAPIClient.send`
(`SavoroIOS/Savoro/Core/API/APIClient.swift:74-91`) has ZERO test coverage — every existing "client"
test only inspects requests built by `makeURLRequest`: `ScaffoldTests.swift:33-47`
(launch-environment request), `:2205-2229` (contract-exact bodies), and `:3236-3257` (authenticated
JSON request). Today `send` maps any non-2xx to `APIClientError.httpStatus(Int)` and DISCARDS the
response body, so the server's error envelope `{ "error": { "code", "message" } }`
(`apps/api/src/errors.ts:22-24`) is never decoded, and 401 is indistinguishable from 500 at call
sites. This ticket is deliberately scoped so another fresh agent can verify and land it
independently.

## Approach
1. Build a `StubURLProtocol` harness in `SavoroTests/` (register per-test via an ephemeral
`URLSessionConfiguration` with `protocolClasses = [StubURLProtocol.self]`; inject that session
through the existing `URLSessionAPIClient(session:)` initializer at `APIClient.swift:62-72`).
Handlers keyed per test: return (status, headers, body) or throw a transport error.
2. Harden `send`:
   - on non-2xx, attempt to decode the error envelope; extend `APIClientError` with a case carrying
     `(statusCode, code, message)` (envelope-less bodies keep the plain `httpStatus` behavior);
   - on 401 specifically, invoke a central unauthorized handler before throwing — add an injectable
     `@Sendable` hook (e.g. `onUnauthorized` closure, default no-op) to `URLSessionAPIClient`. Its
     production wiring is: clear the session via P4.1's `SessionStore` and signal the root state
     transition — the root state machine itself lands in P4.5; here the hook exists, is invoked exactly
     once per 401, and is testable.
3. Tests (`SavoroTests/URLSessionAPIClientSendTests.swift`), all through the REAL `send`:
   - 2xx decode: stubbed 200 + valid JSON returns the typed response;
   - 401: stubbed 401 with the real envelope → error thrown AND the unauthorized hook fired once with
     the session cleared through an `InMemoryTokenStore`-backed `SessionStore`;
   - error envelope decode (named test, e.g. `testErrorEnvelopeDecodesCodeAndMessage`): stubbed 422
     `{"error":{"code":"validation_failed","message":"…"}}` surfaces code and message;
   - malformed JSON on a 2xx → `APIClientError.decoding`, not a crash;
   - end-to-end mid-onboarding payload: stub `GET /v1/me` returning P4.3's fresh-account fixture with
     `"username": null` and decode `CurrentUser` through the real client.
4. Non-401 errors must NOT fire the unauthorized hook (assert on the 422 case).

## Files
- `SavoroIOS/Savoro/Core/API/APIClient.swift`
- `SavoroIOS/SavoroTests/URLSessionAPIClientSendTests.swift` (new, incl. the StubURLProtocol)
- `SavoroIOS/Savoro.xcodeproj/project.pbxproj` (only if registration requires it)

This fence is the send path and its first real coverage; do not absorb the root state machine
(P4.5), AppEnvironment changes (P4.6), or MockAPIClient rework.

## Done when
- All five stubbed-path tests pass through the real `send` — none replaced by a `MockAPIClient`
  stand-in (runbook: never swap a live-path assertion for a mock that cannot fail the production
  seam).
- The error envelope case exists on `APIClientError` and callers can read `code`/`message`.
- 401 fires the injected handler exactly once and the session token is cleared; 422 does not fire it.
- Existing request-building tests (`ScaffoldTests.swift:33-47`, `:3236-3257`) still pass unmodified.
- Required negative witness: break the error-envelope decode in the final code (e.g. decode the
  wrong key) → `testErrorEnvelopeDecodesCodeAndMessage` goes red; restore; rerun green.

## Verify

```bash
cd SavoroIOS && xcodebuild test -scheme Savoro -destination 'platform=iOS Simulator,name=iPhone 17'
```
Record in `_LEDGER.md`: derived test count before/after, the five new test names, and the exact red

## Watch out
- `APIClientError` is `Equatable` with `decoding` stringly-typed (`APIClient.swift:124-133`); extend
  it without breaking existing equality-based assertions elsewhere in the suite.
- `URLProtocol.stopLoading` and handler state are racy if handlers are stored globally mutable — key
  handlers per request or serialize access, or the suite flakes.
- Do not make `onUnauthorized` async-blocking in a way that deadlocks `send`; fire-and-record is
  enough for this ticket, P4.5 owns the state transition.
- Retries on 401 are out of scope — one throw, one hook call; no silent token refresh exists in this
  architecture (opaque sessions, locked decision 1).
- If P4.3's landed `CurrentUser`/fixtures differ from this packet's assumptions (naming, fixture
  paths), follow the landed code and note it; if `send`'s compiled shape has diverged from lines
  74-91 cited here, re-verify before editing and mark blocked only on real contradiction.
