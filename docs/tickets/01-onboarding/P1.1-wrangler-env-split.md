# P1.1 — Split wrangler config into local and preview environments

Phase: 1 · Preview infrastructure
Track: backend
Execution: **autonomous**
Depends on: P0.3
Supersedes: OB-10 and the config half of OB-7

## Goal
Give `apps/api/wrangler.jsonc` an explicit local/preview environment split and write the deploy runbook, without deploying anything.

## Context and design direction
Read `_DESIGN.md` and `_RUNBOOK.md` before editing. Today `apps/api/wrangler.jsonc` has a single flat config: the D1 binding `DB` (`database_name: "savoro-dev"`) carries the zero-UUID placeholder `"00000000-0000-0000-0000-000000000000"` (line 13), and `vars.APPLE_BUNDLE_ID` is `"com.savoro.app"` (line 19). The real iOS app's `PRODUCT_BUNDLE_IDENTIFIER` is `com.savoro.Savoro` for both Debug and Release (`SavoroIOS/Savoro.xcodeproj/project.pbxproj`, lines 196–197) — the wrangler value is stale and must be corrected; API tests are unaffected because `test/auth-apple.test.ts` injects `APPLE_BUNDLE_ID: 'com.savoro.test'`. No deploy happens in this ticket: Wrangler is unauthenticated until P1.2, so the preview `database_id` stays a clearly-labeled placeholder here. This ticket is deliberately scoped so another fresh agent can verify and land it independently.

## Files
- `apps/api/wrangler.jsonc`
- `apps/api/package.json` (scripts only)
- `apps/api/README.md` (pointer to the runbook)
- `docs/deploy-runbook.md` (new)

This fence is config + docs only; no `src/` or test changes belong here — do not absorb adjacent work.

## Approach
1. Restructure `wrangler.jsonc`: keep the top level as the local/dev default (used by `wrangler dev`, vitest via `vitest.config.ts` `configPath`, and the `--local` D1 scripts). Correct top-level `APPLE_BUNDLE_ID` to `com.savoro.Savoro`.
2. Add `"env": { "preview": { ... } }` with its own `d1_databases` block (named envs do NOT inherit bindings — repeat binding `DB`, a preview database name such as `savoro-preview`, `migrations_dir: "migrations"`, and a placeholder `database_id` commented `// replaced with the real id in P1.2`) and its own `vars`: `ENVIRONMENT: "preview"`, `APPLE_BUNDLE_ID: "com.savoro.Savoro"`.
3. Extend `apps/api/package.json` scripts. Today they are `db:migrate:remote: "wrangler d1 migrations apply DB --remote"` (line 11) and `deploy: "wrangler deploy"` (line 7). Add preview-targeted variants, e.g. `db:migrate:preview: "wrangler d1 migrations apply DB --env preview --remote"` and `deploy:preview: "wrangler deploy --env preview"`. Leave existing local scripts untouched.
4. Write `docs/deploy-runbook.md`: prerequisites (`wrangler login`, `wrangler whoami`), one-time provisioning (P1.2's `wrangler d1 create`, pasting the real `database_id`), migrate + deploy commands (the exact package.json scripts), smoke checks (P1.3), and a "Never commit credentials" section: no API tokens, no account IDs beyond what wrangler.jsonc requires, no session tokens, and `seed/local-dev.sql` (which contains the fixed `dev-alice-token`) is never applied remotely — remote seeding goes only through P1.4's tooling.
5. Add a short "Deploying" pointer in `apps/api/README.md` linking to `docs/deploy-runbook.md`.

### Implementation sketch
```jsonc
{
  "name": "savoro-api",
  "main": "src/index.ts",
  "compatibility_date": "2025-09-06",
  "compatibility_flags": ["nodejs_compat"],
  // Top level = local dev + vitest default (wrangler dev, --local D1 scripts).
  "d1_databases": [
    { "binding": "DB", "database_name": "savoro-dev",
      "database_id": "00000000-0000-0000-0000-000000000000", "migrations_dir": "migrations" }
  ],
  "vars": { "ENVIRONMENT": "development", "APPLE_BUNDLE_ID": "com.savoro.Savoro" },
  "env": {
    "preview": {
      // Named envs inherit nothing binding-shaped: repeat DB and vars here.
      "d1_databases": [
        { "binding": "DB", "database_name": "savoro-preview",
          "database_id": "REPLACE-IN-P1.2", "migrations_dir": "migrations" }
      ],
      "vars": { "ENVIRONMENT": "preview", "APPLE_BUNDLE_ID": "com.savoro.Savoro" }
    }
  }
}
```

## Done when
- `wrangler.jsonc` parses and carries a top-level local default plus an `env.preview` section with its own `DB` binding and `APPLE_BUNDLE_ID=com.savoro.Savoro`; the preview `database_id` is an explicit placeholder awaiting P1.2.
- Top-level `APPLE_BUNDLE_ID` no longer says `com.savoro.app`.
- `bun run test` and `bun run typecheck` still pass in `apps/api` (the test pool reads this config file).
- `docs/deploy-runbook.md` exists with exact commands and the never-commit-credentials section, including the `seed/local-dev.sql` prohibition.
- No deploy, no `wrangler login`, no remote command was run.

## Verify
```bash
cd apps/api && bun run test && bun run typecheck
cd apps/api && bunx wrangler deploy --env preview --dry-run --outdir /tmp/wrangler-dry 2>&1 | head -30
```
Record in `_LEDGER.md`: derived test count, the dry-run output showing the preview env resolves (it may warn about the placeholder id — that is expected), and the runbook path.

## Watch out
- Named wrangler environments do not inherit `d1_databases` or `vars` from the top level — an empty `env.preview` silently deploys with no DB binding. Repeat both blocks.
- Do not put a real database_id here; that is P1.2's supervised action. If you find yourself needing `wrangler login`, stop — out of scope.
- Do not touch `SavoroIOS/` — the bundle-id fix is wrangler-side only.
- vitest boots from this config (`vitest.config.ts` `wrangler: { configPath: './wrangler.jsonc' }`); if the suite fails after the restructure, the top-level default was broken — fix the config, never the tests.
- If compiled reality contradicts this packet (e.g. an env split already exists, or the placeholder id is gone), mark the ticket blocked in your report with the exact lines observed rather than improvising.
